## Leap of Faith؛ اعتماد به درستی تابع

برای درک نحوه اجرای برنامه، می‌توانیم جریان اجرای آن را مرحله‌به‌مرحله دنبال کنیم. اما وقتی برنامه بزرگ‌تر و پیچیده‌تر می‌شود، این کار به‌سرعت دشوار و گیج‌کننده خواهد شد.

روش دیگری هم وجود دارد که به آن **Leap of Faith** یا «جهش ایمانی» می‌گوییم.

ایده ساده است: وقتی به فراخوانی یک تابع می‌رسیم، به‌جای اینکه وارد بدنه آن شویم و تمام مراحل اجرای آن را دنبال کنیم، فرض می‌کنیم تابع درست کار می‌کند و نتیجه مورد انتظار را برمی‌گرداند.

در واقع، همین حالا هم هنگام استفاده از توابع داخلی Python این کار را انجام می‌دهیم. مثلاً وقتی `abs()` یا `math.sqrt()` را فراخوانی می‌کنیم، سراغ کد داخلی آن‌ها نمی‌رویم تا ببینیم چطور پیاده‌سازی شده‌اند؛ فقط فرض می‌کنیم درست کار می‌کنند.

همین طرز فکر را می‌توانیم درباره توابعی که خودمان نوشته‌ایم هم به کار ببریم.

مثلاً قبلاً تابعی به نام `is_divisible` نوشتیم که مشخص می‌کند آیا یک عدد بر عدد دیگر بخش‌پذیر است یا نه. وقتی مطمئن شدیم این تابع درست کار می‌کند، دیگر لازم نیست هر بار که از آن استفاده می‌کنیم، دوباره بدنه‌اش را بررسی کنیم.

این روش برای توابع بازگشتی هم کاربرد دارد.

فرض کن در تابع `factorial` به فراخوانی بازگشتی می‌رسیم. به‌جای دنبال کردن تمام مراحل اجرای تابع، فرض می‌کنیم فراخوانی `factorial(n - 1)` به‌درستی کار می‌کند. حالا فقط باید از خودمان بپرسیم:

«اگر بتوانم فاکتوریل عدد (n-1) را محاسبه کنم، آیا می‌توانم فاکتوریل عدد (n) را هم به دست بیاورم؟»

طبق تعریف بازگشتی فاکتوریل، پاسخ مثبت است؛ کافی است نتیجه فاکتوریل (n-1) را در (n) ضرب کنیم:

[  
n! = n \times (n-1)!  
]

البته کمی عجیب به نظر می‌رسد که قبل از کامل شدن یک تابع، فرض کنیم درست کار می‌کند! اما دقیقاً به همین دلیل نام این روش را **Leap of Faith** گذاشته‌اند.

## Fibonacci

بعد از `factorial`، یکی از رایج‌ترین مثال‌ها برای آشنایی با توابع بازگشتی، دنباله فیبوناچی (Fibonacci) است.

این دنباله به شکل زیر تعریف می‌شود:

[  
\begin{aligned}  
fibonacci(0) &= 0 \  
fibonacci(1) &= 1 \  
fibonacci(n) &= fibonacci(n-1) + fibonacci(n-2)  
\end{aligned}  
]

یعنی دو مقدار ابتدایی دنباله به‌ترتیب صفر و یک هستند و هر مقدار بعدی از جمع دو مقدار قبلی به دست می‌آید.

حالا بیایید این تعریف را در Python پیاده‌سازی کنیم:

!!! example "Python"

    ```python
    def fibonacci(n):
        if n == 0:
            return 0
        elif n == 1:
            return 1
        else:
            return fibonacci(n-1) + fibonacci(n-2)
    ```

اگر بخواهیم جریان اجرای این تابع را برای مقادیر کوچک `n` هم مرحله‌به‌مرحله دنبال کنیم، خیلی زود سردرگم می‌شویم!

اما با استفاده از روش Leap of Faith، کار ساده‌تر است. فرض می‌کنیم دو فراخوانی بازگشتی زیر:

```
fibonacci(n-1)
fibonacci(n-2)
```

هرکدام نتیجه درست خودشان را برمی‌گردانند. در این صورت، جمع کردن آن دو نتیجه دقیقاً همان چیزی است که برای محاسبه `fibonacci(n)` نیاز داریم.

پس بدون اینکه لازم باشد تمام جزئیات اجرای فراخوانی‌های بازگشتی را دنبال کنیم، می‌توانیم درستی منطق تابع را بررسی کنیم.

**یک نکته:** این روش محاسبه فیبوناچی از نظر کارایی بسیار ضعیف است. دلیل آن این است که بسیاری از محاسبات تکراری چندین بار انجام می‌شوند. بعداً در مبحث Memoization بررسی می‌کنیم که چرا این اتفاق می‌افتد و چطور می‌توانیم آن را بهبود دهیم.

## Checking Types؛ بررسی نوع داده‌ها

حالا یک سؤال جالب:

اگر تابع `factorial` را با عدد اعشاری `1.5` فراخوانی کنیم، چه اتفاقی می‌افتد؟

!!! example "Python"

    ```python
    factorial(1.5)
    ```

    **Output:**

    ```text
    RecursionError: maximum recursion depth exceeded in comparison
    ```

به نظر می‌رسد با یک بازگشت بی‌نهایت (Infinite Recursion) مواجه شده‌ایم. اما چرا؟ مگر تابع ما شرط پایه (Base Case) ندارد؟

```
if n == 0:
    return 1
```

مشکل اینجاست که شرط پایه فقط زمانی برقرار می‌شود که `n` دقیقاً برابر صفر باشد. اگر ورودی عدد صحیح نباشد، ممکن است هیچ‌وقت به این شرط نرسیم.

بیایید ببینیم برای ورودی `1.5` چه اتفاقی می‌افتد:

1. در اولین فراخوانی، مقدار `n` برابر `1.5` است.
    
2. در فراخوانی بعدی، مقدار `n` برابر `0.5` می‌شود.
    
3. در فراخوانی بعد از آن، مقدار `n` برابر `-0.5` خواهد بود.
    
4. از اینجا به بعد، مقدار `n` همچنان کوچک‌تر و منفی‌تر می‌شود.
    

پس مقدار `n` هیچ‌وقت به صفر نمی‌رسد و تابع دائماً خودش را فراخوانی می‌کند تا در نهایت Python با خطای `RecursionError` اجرای آن را متوقف کند.

### استفاده از isinstance

برای جلوگیری از چنین مشکلی، می‌توانیم قبل از شروع محاسبات، نوع ورودی را بررسی کنیم.

Python تابع داخلی `isinstance()` را برای بررسی نوع یک مقدار در اختیارمان قرار می‌دهد.

مثلاً اگر بخواهیم بررسی کنیم که یک مقدار از نوع `int` است یا نه:

!!! example "Python"

    ```python
    isinstance(3, int)
    ```

    **Output:**

    ```text
    True
    ```

و برای یک عدد اعشاری:

!!! example "Python"

    ```python
    isinstance(1.5, int)
    ```

    **Output:**

    ```text
    False
    ```

همان‌طور که می‌بینیم، `isinstance()` یک مقدار بولی (`True` یا `False`) برمی‌گرداند و مشخص می‌کند که مقدار ورودی از نوع موردنظر هست یا نه.

حالا می‌توانیم تابع `factorial` را طوری بازنویسی کنیم که قبل از شروع بازگشت، ورودی را بررسی کند:

!!! example "Python"

    ```python
    def factorial(n):
        if not isinstance(n, int):
            print('factorial is only defined for integers.')
            return None
        elif n < 0:
            print('factorial is not defined for negative numbers.')
            return None
        elif n == 0:
            return 1
        else:
            return n * factorial(n-1)
    ```

بیایید ببینیم چه تغییراتی ایجاد کردیم.

**اول: بررسی نوع ورودی**

```
if not isinstance(n, int):
    print('factorial is only defined for integers.')
    return None
```

در ابتدای تابع بررسی می‌کنیم که آیا `n` از نوع `int` است یا نه.

اگر ورودی عدد صحیح نباشد، پیام خطا نمایش داده می‌شود و تابع با `return None` به پایان می‌رسد.

برای مثال:

!!! example "Python"

    ```python
    factorial('crunchy frog')
    ```

    **Output:**

    ```text
    factorial is only defined for integers.
    ```

**دوم: بررسی منفی نبودن عدد**

```
elif n < 0:
    print('factorial is not defined for negative numbers.')
    return None
```

اگر ورودی عدد صحیح باشد، بررسی می‌کنیم که منفی نباشد. فاکتوریل در این تابع برای اعداد منفی تعریف نشده است؛ بنابراین در صورت منفی بودن ورودی، پیام مناسبی نمایش می‌دهیم و با `return None` از تابع خارج می‌شویم.

مثلاً:

!!! example "Python"

    ```python
    factorial(-2)
    ```

    **Output:**

    ```text
    factorial is not defined for negative numbers.
    ```

**سوم: اجرای محاسبه بازگشتی**

اگر از دو بررسی قبلی عبور کنیم، می‌دانیم که `n` یک عدد صحیح نامنفی است. بنابراین می‌توانیم با اطمینان از اینکه بازگشت در نهایت به شرط پایه می‌رسد، محاسبه فاکتوریل را انجام دهیم:

```
elif n == 0:
    return 1
else:
    return n * factorial(n-1)
```

به این ترتیب، قبل از اجرای منطق اصلی تابع، ورودی را اعتبارسنجی کرده‌ایم.

به فرایند بررسی پارامترهای یک تابع برای اطمینان از درست بودن نوع و مقدار آن‌ها، **Input Validation** یا «اعتبارسنجی ورودی» می‌گوییم.

این کار کمک می‌کند تابع فقط با ورودی‌هایی اجرا شود که برای آن‌ها طراحی شده است و از بروز خطاهای قابل پیشگیری جلوگیری شود.

## Debugging؛ اشکال‌زدایی

تقسیم یک برنامه بزرگ به توابع کوچک‌تر، نقاط مشخصی برای بررسی و اشکال‌زدایی (Debugging) ایجاد می‌کند. وقتی تابعی درست کار نمی‌کند، معمولاً باید سه احتمال را بررسی کنیم:

1. **مشکل در آرگومان‌های ورودی تابع:** ممکن است تابع آرگومان‌های نامناسبی دریافت کرده باشد؛ یعنی یکی از پیش‌شرط‌ها (Preconditions) نقض شده باشد.
    
2. **مشکل در خود تابع:** ممکن است منطق داخلی تابع اشتباه باشد و نتیجه مورد انتظار را تولید نکند؛ یعنی پس‌شرط (Postcondition) نقض شده باشد.
    
3. **مشکل در کد فراخواننده:** ممکن است تابع درست کار کند، اما کدی که آن را فراخوانی کرده، از مقدار بازگشتی (Return Value) به‌شکل اشتباهی استفاده کند یا اصلاً از آن استفاده نکند.
    

حالا چطور این سه احتمال را بررسی کنیم؟

### ۱. بررسی آرگومان‌های ورودی

برای اینکه احتمال اول را بررسی کنیم، می‌توانیم در ابتدای تابع یک دستور `print()` قرار دهیم تا مقادیر پارامترها را نمایش دهد. حتی می‌توانیم نوع داده آن‌ها را هم چاپ کنیم.

مثلاً:

```
def factorial(n):
    print("n =", n, "type =", type(n))
    # ادامه تابع
```

به این ترتیب، قبل از اینکه تابع وارد منطق اصلی خودش شود، می‌توانیم ببینیم دقیقاً چه مقداری دریافت کرده است.

راه دیگر این است که پیش‌شرط‌های تابع را به‌صورت صریح بررسی کنیم؛ همان کاری که در بخش قبل با `isinstance()` انجام دادیم.

### ۲. بررسی مقدار بازگشتی تابع

اگر مطمئن شدیم پارامترهای ورودی درست هستند، باید سراغ منطق داخلی تابع برویم.

برای این کار می‌توانیم قبل از هر دستور `return` یک `print()` قرار دهیم تا مقدار بازگشتی را نمایش دهد.

همچنین بهتر است تابع را با ورودی‌هایی آزمایش کنیم که بررسی نتیجه آن‌ها ساده باشد. هرچه نتیجه مورد انتظار مشخص‌تر باشد، تشخیص اشتباهات هم راحت‌تر خواهد بود.

### ۳. بررسی نحوه استفاده از مقدار بازگشتی

اگر به نظر می‌رسد خود تابع درست کار می‌کند، باید محل فراخوانی آن را بررسی کنیم.

ممکن است تابع مقدار درستی برگرداند، اما کد فراخواننده از آن به‌درستی استفاده نکند؛ یا حتی مقدار بازگشتی را کاملاً نادیده بگیرد.

پس همیشه به خاطر داشته باش: درست بودن یک تابع به‌تنهایی کافی نیست؛ نحوه استفاده از نتیجه آن هم اهمیت دارد.

## مشاهده جریان اجرای تابع با print

قرار دادن دستورهای `print()` در ابتدا و انتهای یک تابع می‌تواند جریان اجرای برنامه را واضح‌تر کند.

برای مثال، بیایید نسخه‌ای از تابع `factorial` را بنویسیم که هنگام اجرا، اطلاعاتی درباره فراخوانی‌ها و مقادیر بازگشتی نمایش می‌دهد:

!!! example "Python"

    ```python
    def factorial(n):
        space = ' ' * (4 * n)
        print(space, 'factorial', n)

        if n == 0:
            print(space, 'returning 1')
            return 1
        else:
            recurse = factorial(n-1)
            result = n * recurse
            print(space, 'returning', result)
            return result
    ```

در این نسخه، دو متغیر جدید داریم:

- `space`: رشته‌ای از فاصله‌ها (Space Characters) است که برای تنظیم تورفتگی خروجی استفاده می‌شود.
    
- `recurse`: نتیجه فراخوانی بازگشتی `factorial(n-1)` را نگه می‌دارد.
    

چرا اصلاً به `space` نیاز داریم؟

به این دلیل که می‌خواهیم فراخوانی‌های تو در تو را از یکدیگر تشخیص دهیم. هرچه مقدار `n` بزرگ‌تر باشد، تعداد فاصله‌های ابتدای پیام هم بیشتر می‌شود. در نتیجه، عمق فراخوانی‌های بازگشتی را می‌توانیم از روی تورفتگی خروجی تشخیص دهیم.

حالا تابع را با مقدار `4` اجرا کنیم:

!!! example "Python"

    ```python
    factorial(4)
    ```

    **Output:**

    ```text
                 factorial 4
             factorial 3
         factorial 2
     factorial 1
    factorial 0
    returning 1
     returning 1
         returning 2
             returning 6
                 returning 24

    24
    ```

به تورفتگی خروجی دقت کن.

در ابتدا، تابع با مقدار `4` فراخوانی می‌شود. سپس برای محاسبه فاکتوریل، خودش را با مقدار `3` فراخوانی می‌کند. این روند تا رسیدن به `factorial(0)` ادامه پیدا می‌کند.

وقتی به شرط پایه می‌رسیم، مقدار `1` برگردانده می‌شود. بعد از آن، فراخوانی‌های قبلی یکی‌یکی از حالت انتظار خارج می‌شوند و محاسبات خودشان را انجام می‌دهند:

[  
\begin{aligned}  
factorial(0) &= 1 \  
factorial(1) &= 1 \times 1 = 1 \  
factorial(2) &= 2 \times 1 = 2 \  
factorial(3) &= 3 \times 2 = 6 \  
factorial(4) &= 4 \times 6 = 24  
\end{aligned}  
]

به این ترتیب، می‌توانیم هم مسیر پایین رفتن فراخوانی‌های بازگشتی و هم مسیر برگشت مقادیر را مشاهده کنیم.

وقتی درک جریان اجرای برنامه دشوار می‌شود، چنین خروجی‌هایی واقعاً مفید هستند.

البته طراحی این نوع ابزارهای کمکی برای اشکال‌زدایی (Scaffolding) کمی زمان می‌برد؛ اما حتی مقدار کمی Scaffolding می‌تواند در زمان Debugging صرفه‌جویی زیادی ایجاد کند.
