## Search؛ جست‌وجو

حالا که نسخه ساده‌تری از تابع `has_e()` را داریم، می‌توانیم آن را تعمیم دهیم و تابعی عمومی‌تر به نام `uses_any()` بسازیم.

این تابع دو پارامتر دریافت می‌کند:

- `word`: کلمه‌ای که می‌خواهیم بررسی کنیم.
    
- `letters`: رشته‌ای شامل حروفی که به دنبال آن‌ها هستیم.
    

اگر کلمه حداقل یکی از حروف موجود در `letters` را داشته باشد، تابع `True` و در غیر این صورت `False` برمی‌گرداند.

پیاده‌سازی تابع به این شکل است:

!!! example "Python"

````
```python
def uses_any(word, letters):
    for letter in word.lower():
        if letter in letters.lower():
            return True

    return False
```
````

بیایید چند مثال را بررسی کنیم.

در مثال اول، می‌خواهیم ببینیم آیا کلمه `banana` حداقل یکی از حروف صدادار انگلیسی (`a`, `e`, `i`, `o`, `u`) را دارد یا نه:

!!! example "Python"

````
```python
uses_any('banana', 'aeiou')
```

**Output:**

```text
True
```
````

چون کلمه `banana` شامل حرف `a` است، نتیجه `True` خواهد بود.

در مثال بعدی، حروف `x`, `y`, `z` را بررسی می‌کنیم:

!!! example "Python"

````
```python
uses_any('apple', 'xyz')
```

**Output:**

```text
False
```
````

هیچ‌کدام از این سه حرف در کلمه `apple` وجود ندارند؛ بنابراین نتیجه `False` است.

یک نکته دیگر هم وجود دارد. همان‌طور که می‌بینی، در ابتدای تابع از `lower()` استفاده کرده‌ایم. این کار باعث می‌شود تابع بدون توجه به بزرگ یا کوچک بودن حروف ورودی درست کار کند:

!!! example "Python"

````
```python
uses_any('Banana', 'AEIOU')
```

**Output:**

```text
True
```
````

### الگوی Linear Search

ساختار تابع `uses_any()` شباهت زیادی به `has_e()` دارد.

ابتدا حروف موجود در `word` را با یک حلقه `for` یکی‌یکی بررسی می‌کنیم. برای هر حرف، بررسی می‌کنیم که آیا در رشته `letters` هم وجود دارد یا نه.

اگر حتی یکی از حروف پیدا شود، بلافاصله `True` برمی‌گردانیم و اجرای تابع تمام می‌شود.

اما اگر تمام حروف کلمه بررسی شوند و هیچ‌کدام در `letters` وجود نداشته باشند، اجرای حلقه به پایان می‌رسد و تابع در نهایت `False` برمی‌گرداند.

به این الگو **Linear Search** یا «جست‌وجوی خطی» می‌گوییم.

در این روش، عناصر مجموعه موردنظر را به‌ترتیب بررسی می‌کنیم تا عنصر موردنظر را پیدا کنیم یا مطمئن شویم که چنین عنصری وجود ندارد.

در تمرین‌های انتهای این فصل، توابع بیشتری با استفاده از همین الگو خواهیم نوشت.

## Doctest؛ آزمایش تابع با Docstring

در بخش Docstrings یاد گرفتیم که می‌توانیم با استفاده از Docstring توضیح دهیم یک تابع چه کاری انجام می‌دهد.

اما آیا می‌دانستی می‌توانیم از همین Docstring برای آزمایش تابع هم استفاده کنیم؟

این قابلیت در Python با نام **Doctest** شناخته می‌شود.

بیایید نسخه‌ای از تابع `uses_any()` بنویسیم که داخل Docstring آن چند تست هم قرار داده شده است:

!!! example "Python"

````
```python
def uses_any(word, letters):
    """Checks if a word uses any of a list of letters.

    >>> uses_any('banana', 'aeiou')
    True
    >>> uses_any('apple', 'xyz')
    False
    """
    for letter in word.lower():
        if letter in letters.lower():
            return True

    return False
```
````

به قسمت Docstring دقت کن. دو تست داخل آن قرار داده‌ایم.

هر تست با علامت `>>>` شروع می‌شود. این علامت در بعضی محیط‌های Python به‌عنوان Prompt استفاده می‌شود و نشان می‌دهد که کاربر می‌تواند دستور خود را وارد کند.

در Doctest هم بعد از `>>>` عبارتی قرار می‌گیرد که معمولاً یک فراخوانی تابع است. خط بعدی، نتیجه‌ای را نشان می‌دهد که انتظار داریم آن عبارت تولید کند.

برای مثال، در تست اول:

```
>>> uses_any('banana', 'aeiou')
True
```

چون کلمه `banana` شامل حرف `a` است، انتظار داریم نتیجه `True` باشد.

در تست دوم:

```
>>> uses_any('apple', 'xyz')
False
```

چون هیچ‌کدام از حروف `x`, `y`, `z` در کلمه `apple` وجود ندارند، نتیجه مورد انتظار `False` است.

### اجرای Doctest

برای اجرای این تست‌ها، ابتدا باید ماژول داخلی `doctest` را وارد کنیم و از تابع `run_docstring_examples()` استفاده کنیم.

برای ساده‌تر شدن کار، تابع کمکی زیر را تعریف می‌کنیم که یک شیء تابع (Function Object) را به‌عنوان آرگومان دریافت می‌کند:

!!! example "Python"

````
```python
from doctest import run_docstring_examples

def run_doctests(func):
    run_docstring_examples(func, globals(), name=func.__name__)
```
````

در این کد با دو مفهوم `globals` و `__name__` روبه‌رو می‌شویم که هنوز درباره آن‌ها صحبت نکرده‌ایم. فعلاً لازم نیست نگران جزئیاتشان باشیم؛ کافی است بدانیم این تابع کمکی، تست‌های موجود در Docstring تابع موردنظر را اجرا می‌کند.

حالا می‌توانیم تابع `uses_any()` را به این شکل آزمایش کنیم:

!!! example "Python"

````
```python
run_doctests(uses_any)
```
````

تابع `run_doctests()` عبارت‌های موجود در Docstring را پیدا می‌کند و آن‌ها را اجرا می‌کند.

اگر نتیجه واقعی هر تست با نتیجه مورد انتظار مطابقت داشته باشد، آن تست موفق خواهد بود. در غیر این صورت، تست شکست می‌خورد و اطلاعات مربوط به اختلاف نتایج نمایش داده می‌شود.

یک نکته جالب: اگر تمام تست‌ها موفق باشند، `run_doctests()` هیچ خروجی‌ای نمایش نمی‌دهد!

پس در اینجا سکوت نشانه خوبی است؛ یعنی همه تست‌ها با موفقیت اجرا شده‌اند.

### مشاهده نتیجه تست ناموفق

حالا بیایید ببینیم اگر تابع اشتباه پیاده‌سازی شده باشد، چه اتفاقی می‌افتد.

در نسخه زیر، عمداً یک اشتباه قرار داده‌ایم:

!!! example "Python"

````
```python
def uses_any_incorrect(word, letters):
    """Checks if a word uses any of a list of letters.

    >>> uses_any_incorrect('banana', 'aeiou')
    True
    >>> uses_any_incorrect('apple', 'xyz')
    False
    """
    for letter in word.lower():
        if letter in letters.lower():
            return True
        else:
            return False     # INCORRECT!
```
````

حالا تست‌های این تابع را اجرا می‌کنیم:

!!! example "Python"

````
```python
run_doctests(uses_any_incorrect)
```

**Output:**

```text
**********************************************************************
File "__main__", line 4, in uses_any_incorrect
Failed example:
    uses_any_incorrect('banana', 'aeiou')
Expected:
    True
Got:
    False
```
````

Doctest اطلاعات مفیدی درباره تست ناموفق نمایش می‌دهد:

- **Failed example:** دستوری که تست آن شکست خورده است.
    
- **Expected:** نتیجه‌ای که انتظار داشتیم تابع برگرداند.
    
- **Got:** نتیجه‌ای که تابع واقعاً برگردانده است.
    

در این مثال، انتظار داشتیم فراخوانی `uses_any_incorrect('banana', 'aeiou')` مقدار `True` را برگرداند، اما نتیجه واقعی `False` بوده است.

حالا سؤال اینجاست: چرا چنین اتفاقی افتاده است؟

مشکل در محل قرارگیری `else` و `return False` است. تابع به‌محض اینکه اولین حرف کلمه را بررسی می‌کند و متوجه می‌شود آن حرف در `letters` وجود ندارد، بلافاصله `False` برمی‌گرداند؛ در نتیجه فرصت بررسی حروف بعدی را پیدا نمی‌کند.

برای مثال، اولین حرف `banana` برابر `b` است. چون `b` در `aeiou` وجود ندارد، تابع همان‌جا متوقف می‌شود؛ درحالی‌که حرف `a` در ادامه کلمه وجود دارد.

**نکته مهم:** در جست‌وجوی خطی، وقتی یک مورد مطابق با شرط پیدا شد، می‌توانیم فوراً نتیجه مثبت را برگردانیم؛ اما برای اعلام نتیجه منفی باید تمام عناصر را بررسی کرده باشیم.

به همین دلیل، `return False` باید بعد از حلقه قرار بگیرد، نه داخل آن.

این دقیقاً همان اشتباهی است که نسخه صحیح `uses_any()` از آن جلوگیری می‌کند.
