## مقادیر بازگشتی و شرط‌ها (Return Values and Conditionals)

حالا که با دستور `return` آشنا شدیم، بیایید ببینیم چطور می‌توانیم از آن در کنار شرط‌ها استفاده کنیم.

فرض کن پایتون تابع داخلی `abs()` را در اختیارمان نمی‌گذاشت. در این صورت می‌توانستیم تابعی برای محاسبه قدرمطلق یک عدد بنویسیم:

!!! example "Python"

    ```python
    def absolute_value(x):
        if x < 0:
            return -x
        else:
            return x
    ```

منطق تابع ساده است:

- اگر `x` منفی باشد، دستور `return -x` اجرا می‌شود و مقدار مثبت آن برگردانده می‌شود. با اجرای `return`، تابع بلافاصله به پایان می‌رسد.
    
- در غیر این صورت، دستور `return x` اجرا می‌شود و مقدار خود `x` برگردانده می‌شود.
    

بنابراین این تابع برای تمام ورودی‌ها درست عمل می‌کند.

اما هنگام استفاده از `return` در شرط‌ها، باید به یک نکته مهم توجه کنیم:

**باید مطمئن شویم تمام مسیرهای ممکن اجرای تابع به یک دستور** `**return**` **می‌رسند.**

برای درک بهتر، نسخه اشتباهی از همین تابع را ببین:

!!! example "Python"

    ```python
    def absolute_value_wrong(x):
        if x < 0:
            return -x

        if x > 0:
            return x
    ```

حالا اگر مقدار صفر را به این تابع بدهیم، چه اتفاقی می‌افتد؟

!!! example "Python"

    ```python
    absolute_value_wrong(0)
    ```

    **Output:**

    ```text
    ```

هیچ چیزی نمایش داده نمی‌شود!

مشکل کجاست؟

وقتی `x` برابر با صفر باشد:

- شرط اول، یعنی `x < 0`، برقرار نیست.
    
- شرط دوم، یعنی `x > 0`، نیز برقرار نیست.
    

در نتیجه، هیچ‌کدام از دستورهای `return` اجرا نمی‌شوند و تابع بدون رسیدن به یک `return` صریح به پایان می‌رسد.

همان‌طور که قبلاً یاد گرفتیم، اگر تابع به دستور `return` نرسد، مقدار `None` را برمی‌گرداند. به همین دلیل Jupyter چیزی نمایش نمی‌دهد.

### کد غیرقابل اجرا (Dead Code)

حالا نسخه دیگری از تابع `absolute_value` را بررسی کنیم که در انتهای آن یک دستور `return` اضافی قرار داده‌ایم:

!!! example "Python"

    ```python
    def absolute_value_extra_return(x):
        if x < 0:
            return -x
        else:
            return x

        return 'This is dead code'
    ```

اگر `x` منفی باشد، دستور `return -x` اجرا می‌شود و تابع به پایان می‌رسد.

اگر `x` منفی نباشد، وارد شاخه `else` می‌شویم، دستور `return x` اجرا می‌شود و باز هم تابع به پایان می‌رسد.

پس در هر دو حالت، اجرای تابع قبل از رسیدن به دستور سوم متوقف می‌شود.

در نتیجه، این دستور هیچ‌وقت اجرا نخواهد شد:

!!! example "Python"

    ```python
    return 'This is dead code'
    ```

به کدی که تحت هیچ شرایطی اجرا نمی‌شود، **Dead Code** می‌گوییم.

Dead Code معمولاً مستقیماً آسیبی به برنامه نمی‌زند؛ اما اغلب نشانه‌ای از درک نادرست منطق برنامه است و ممکن است کسی را که در حال خواندن یا نگهداری کد است، سردرگم کند.

## توسعه تدریجی (Incremental Development)

هرچه توابع بزرگ‌تر و پیچیده‌تری می‌نویسیم، احتمالاً زمان بیشتری را صرف Debugging خواهیم کرد.

برای مدیریت این پیچیدگی، می‌توانیم از روشی به نام **Incremental Development** یا توسعه تدریجی استفاده کنیم.

ایده اصلی این روش بسیار ساده است:

به‌جای اینکه تمام کد را یک‌باره بنویسیم و در انتها آن را آزمایش کنیم، برنامه را مرحله‌به‌مرحله توسعه می‌دهیم و بعد از اضافه‌کردن هر بخش کوچک، آن را آزمایش می‌کنیم.

برای درک بهتر، فرض کن می‌خواهیم تابعی بنویسیم که فاصله بین دو نقطه را محاسبه کند.

مختصات نقطه اول را با `x1` و `y1` و مختصات نقطه دوم را با `x2` و `y2` نشان می‌دهیم.

طبق قضیه فیثاغورس، فاصله بین این دو نقطه از رابطه زیر به دست می‌آید:

\[
distance = \sqrt{(x_2-x_1)^2+(y_2-y_1)^2}  
\]

حالا قبل از نوشتن کد، باید مشخص کنیم تابع موردنظر چه ورودی‌هایی دریافت می‌کند و چه خروجی‌ای باید برگرداند.

- **Inputs (Parameters):** مختصات دو نقطه، یعنی `x1`، `y1`، `x2` و `y2`.
    
- **Output (Return Value):** فاصله بین دو نقطه.
    

پس می‌توانیم ابتدا فقط ساختار کلی تابع را بنویسیم:

!!! example "Python"

    ```python
    def distance(x1, y1, x2, y2):
        return 0.0
    ```

این نسخه هنوز فاصله واقعی را محاسبه نمی‌کند و همیشه مقدار `0.0` را برمی‌گرداند.

اما نکته مهم این است که تابع از نظر ساختاری کامل است: ورودی‌های مشخصی دارد و یک مقدار هم برمی‌گرداند. بنابراین می‌توانیم آن را همین حالا آزمایش کنیم، قبل از اینکه منطق اصلی را به آن اضافه کنیم.

برای آزمایش، از مقادیر نمونه استفاده می‌کنیم:

!!! example "Python"

    ```python
    distance(1, 2, 4, 6)
    ```

    **Output:**

    ```text
    0.0
    ```

چرا این مقادیر را انتخاب کردیم؟

چون اختلاف مختصات افقی برابر با `3` و اختلاف مختصات عمودی برابر با `4` است. در نتیجه، طبق قضیه فیثاغورس باید فاصله برابر با `5` باشد؛ یعنی وتر یک مثلث قائم‌الزاویه با ضلع‌های `3` و `4`.

هنگام آزمایش یک تابع، دانستن نتیجه صحیح از قبل بسیار مفید است؛ چون می‌توانیم خروجی واقعی برنامه را با نتیجه مورد انتظار مقایسه کنیم.

تا اینجا مطمئن شدیم که تابع اجرا می‌شود و یک مقدار برمی‌گرداند. حالا می‌توانیم منطق محاسبه را به‌تدریج به آن اضافه کنیم.

### مرحله اول: محاسبه اختلاف مختصات

ابتدا اختلاف مختصات دو نقطه را محاسبه می‌کنیم.

برای این کار دو متغیر موقت به نام‌های `dx` و `dy` در نظر می‌گیریم:

- `dx` اختلاف مختصات افقی دو نقطه است.
    
- `dy` اختلاف مختصات عمودی دو نقطه است.
    

فعلاً برای اطمینان از صحت محاسبات، این دو مقدار را با `print()` نمایش می‌دهیم:

!!! example "Python"

    ```python
    def distance(x1, y1, x2, y2):
        dx = x2 - x1
        dy = y2 - y1

        print('dx is', dx)
        print('dy is', dy)

        return 0.0
    ```

حالا دوباره تابع را با همان ورودی‌های قبلی آزمایش می‌کنیم:

!!! example "Python"

    ```python
    distance(1, 2, 4, 6)
    ```

    **Output:**

    ```text
    dx is 3
    dy is 4
    0.0
    ```

خروجی همان چیزی است که انتظار داشتیم: مقدار `dx` برابر با `3` و مقدار `dy` برابر با `4` است.

پس می‌دانیم که تابع Argumentها را به‌درستی دریافت کرده و اولین محاسبات را هم درست انجام داده است.

اگر نتیجه اشتباه بود، فقط کافی بود چند خط مربوط به همین مرحله را بررسی کنیم؛ نه اینکه کل تابع را از ابتدا Debug کنیم.

### مرحله دوم: محاسبه مجموع مربع‌ها

حالا سراغ بخش بعدی فرمول فیثاغورس می‌رویم.

باید مربع اختلاف مختصات افقی و عمودی را با هم جمع کنیم:

\[
d^2 = dx^2 + dy^2  
\]

کد را به شکل زیر توسعه می‌دهیم:

!!! example "Python"

    ```python
    def distance(x1, y1, x2, y2):
        dx = x2 - x1
        dy = y2 - y1

        dsquared = dx**2 + dy**2

        print('dsquared is: ', dsquared)

        return 0.0
    ```

دوباره تابع را اجرا می‌کنیم:

!!! example "Python"

    ```python
    distance(1, 2, 4, 6)
    ```

    **Output:**

    ```text
    dsquared is:  25
    0.0
    ```

مقدار `dsquared` برابر با `25` است؛ چون:

\[
3^2 + 4^2 = 9 + 16 = 25  
\]

پس این مرحله هم درست کار می‌کند.

### مرحله سوم: محاسبه فاصله نهایی

در مرحله آخر، فقط کافی است از تابع `math.sqrt()` برای محاسبه جذر مجموع مربع‌ها استفاده کنیم.

!!! example "Python"

    ```python
    def distance(x1, y1, x2, y2):
        dx = x2 - x1
        dy = y2 - y1

        dsquared = dx**2 + dy**2

        result = math.sqrt(dsquared)

        print("result is", result)
    ```

حالا تابع را آزمایش می‌کنیم:

!!! example "Python"

    ```python
    distance(1, 2, 4, 6)
    ```

    **Output:**

    ```text
    result is 5.0
    ```

فاصله محاسبه‌شده برابر با `5.0` است؛ دقیقاً همان مقداری که انتظار داشتیم.

دقت کن که در این مرحله، تابع فقط نتیجه را با `print()` نمایش می‌دهد و هنوز دستور `return` ندارد. بنابراین مقدار بازگشتی آن `None` است. برای تبدیل آن به تابعی که واقعاً فاصله را برمی‌گرداند، باید در ادامه از `return result` استفاده کنیم.

### چرا Incremental Development مفید است؟

در این مثال، تابع را یک‌باره و کامل ننوشتیم. آن را در چند مرحله توسعه دادیم و پس از هر مرحله، نتیجه را بررسی کردیم.

این روش چند مزیت مهم دارد:

- اگر مشکلی ایجاد شود، محدوده جست‌وجو برای پیدا کردن خطا کوچک‌تر است.
    
- می‌توانیم در هر مرحله مطمئن شویم که بخش اضافه‌شده درست کار می‌کند.
    
- به‌جای Debugging یک تابع پیچیده، هر بار فقط بخش کوچکی از منطق را بررسی می‌کنیم.
    

اصل ماجرا این است: **کد را در گام‌های کوچک بنویس، هر گام را آزمایش کن و فقط وقتی از صحت آن مطمئن شدی، سراغ مرحله بعد برو.**
