  

## اشیا و مقادیر (Objects and Values)

وقتی دو متغیر را به یک مقدار نسبت می‌دهیم، می‌دانیم که هر دو به یک مقدار اشاره می‌کنند؛ اما لزوماً نمی‌دانیم که آیا به یک شیء واحد در حافظه اشاره دارند یا به دو شیء جداگانه.

مثلاً:

!!! example "Python"

    ```python
    a = 'banana'
    b = 'banana'
    ```

در این حالت دو وضعیت ممکن است وجود داشته باشد:

- متغیرهای `a` و `b` به دو شیء جداگانه اشاره کنند که مقدار یکسانی دارند.
    
- هر دو متغیر به یک شیء واحد اشاره کنند.
    

برای بررسی اینکه دو متغیر دقیقاً به یک شیء اشاره می‌کنند یا نه، می‌توانیم از عملگر `is` استفاده کنیم:

!!! example "Python"

    ```python
    a = 'banana'
    b = 'banana'
    a is b
    ```

    **Output:**

    ```text
    True
    ```

در این مثال، Python از یک شیء رشته‌ای استفاده کرده و هر دو متغیر `a` و `b` به همان شیء اشاره می‌کنند.

اما وقتی دو لیست جداگانه ایجاد می‌کنیم، وضعیت متفاوت است:

!!! example "Python"

    ```python
    a = [1, 2, 3]
    b = [1, 2, 3]
    a is b
    ```

    **Output:**

    ```text
    False
    ```

چرا نتیجه `False` شد؟ چون با وجود اینکه عناصر دو لیست یکسان هستند، هر کدام یک شیء مستقل محسوب می‌شوند.

در اینجا باید با دو مفهوم مهم آشنا شویم:

- **معادل بودن (Equivalent):** دو شیء از نظر مقدار یا محتوای خود برابر باشند.
    
- **یکسان بودن (Identical):** دو متغیر دقیقاً به یک شیء واحد اشاره کنند.
    

پس دو لیست بالا از نظر محتوا معادل هستند، اما یکسان نیستند.

این دو مفهوم را با یک قانون ساده به خاطر بسپار:

اگر دو شیء یکسان باشند، حتماً معادل هم هستند؛ اما اگر دو شیء معادل باشند، لزوماً یکسان نیستند.

## نام‌های مستعار (Aliasing)

حالا فرض کن یک لیست داریم و می‌خواهیم متغیر دیگری را هم به همان لیست متصل کنیم.

اگر بنویسیم:

!!! example "Python"

    ```python
    a = [1, 2, 3]
    b = a
    b is a
    ```

    **Output:**

    ```text
    True
    ```

این بار نتیجه `True` است؛ چون با اجرای `b = a` یک لیست جدید نساخته‌ایم. فقط متغیر `b` را به همان شیئی متصل کرده‌ایم که `a` به آن اشاره می‌کند.

به ارتباط یک متغیر با یک شیء، **ارجاع (Reference)** می‌گوییم.

در این مثال، دو ارجاع به یک شیء واحد داریم: یکی از طریق `a` و دیگری از طریق `b`.

وقتی یک شیء بیش از یک ارجاع داشته باشد، می‌گوییم آن شیء دارای نام مستعار (Alias) است؛ یعنی چند متغیر مختلف به همان شیء اشاره می‌کنند.

اما این موضوع چه اهمیتی دارد؟

به یاد داری که لیست‌ها Mutable هستند؛ یعنی می‌توانیم محتوای آن‌ها را تغییر دهیم. بنابراین اگر یک شیء از طریق چند متغیر قابل دسترسی باشد، تغییری که با یکی از آن متغیرها ایجاد می‌کنیم، از طریق متغیر دیگر هم قابل مشاهده خواهد بود.

مثلاً:

!!! example "Python"

    ```python
    b[0] = 5
    a
    ```

    **Output:**

    ```text
    [5, 2, 3]
    ```

ما با استفاده از `b` عنصر اول لیست را تغییر دادیم؛ اما وقتی مقدار `a` را بررسی می‌کنیم، می‌بینیم که آن هم تغییر کرده است!

دلیلش ساده است: `a` و `b` دو نام برای دسترسی به یک شیء واحد هستند. بنابراین هر دو تغییر را مشاهده می‌کنند.

این رفتار گاهی بسیار مفید است، اما می‌تواند باعث خطاهای غیرمنتظره هم بشود. ممکن است تابعی را فراخوانی کنیم و تصور کنیم فقط متغیر داخل تابع تغییر کرده است، درحالی‌که همان شیء اصلی را تغییر داده‌ایم.

به همین دلیل، هنگام کار با اشیای تغییرپذیر (Mutable Objects)، باید مراقب Aliasing باشیم.

البته برای اشیای تغییرناپذیر (Immutable Objects) مثل رشته‌ها، این موضوع معمولاً مشکل خاصی ایجاد نمی‌کند.

مثلاً:

!!! example "Python"

    ```python
    a = 'banana'
    b = 'banana'
    ```

فرقی نمی‌کند `a` و `b` به یک شیء رشته‌ای اشاره کنند یا دو شیء جداگانه؛ چون رشته‌ها تغییرناپذیر هستند و نمی‌توانیم محتوای شیء اصلی را از طریق یکی از این ارجاع‌ها تغییر دهیم.

## ارسال لیست به توابع (List Arguments)

وقتی یک لیست را به‌عنوان آرگومان به یک تابع ارسال می‌کنیم، تابع یک ارجاع به همان لیست دریافت می‌کند، نه یک کپی مستقل از آن.

این موضوع اهمیت زیادی دارد؛ چون اگر تابع محتوای لیست را تغییر دهد، تغییرات بعد از پایان اجرای تابع هم باقی می‌مانند و کدی که تابع را فراخوانی کرده است نیز آن‌ها را مشاهده می‌کند.

برای مثال، تابعی به نام `pop_first()` تعریف می‌کنیم که اولین عنصر لیست را با استفاده از متد `pop()` حذف می‌کند و همان عنصر را برمی‌گرداند:

!!! example "Python"

    ```python
    def pop_first(lst):
        return lst.pop(0)
    ```

حالا می‌توانیم این تابع را به شکل زیر فراخوانی کنیم:

!!! example "Python"

    ```python
    letters = ['a', 'b', 'c']
    pop_first(letters)
    ```

    **Output:**

    ```text
    'a'
    ```

مقدار بازگشتی تابع، اولین عنصر لیست یعنی `'a'` است؛ همان عنصری که از لیست حذف شده است.

برای اینکه ببینیم خود لیست چه تغییری کرده، مقدار `letters` را بررسی می‌کنیم:

!!! example "Python"

    ```python
    letters
    ```

    **Output:**

    ```text
    ['b', 'c']
    ```

می‌بینی؟ عنصر اول حذف شده و تغییرات در متغیر اصلی هم قابل مشاهده است.

دلیل این رفتار آن است که پارامتر `lst` درون تابع و متغیر `letters` در بیرون تابع، هر دو به یک شیء واحد اشاره می‌کنند. به عبارت دیگر، این دو متغیر نام‌های مستعار همان لیست هستند.

پس وقتی تابع با استفاده از `lst.pop(0)` لیست را تغییر می‌دهد، در واقع همان شیئی را تغییر داده که `letters` هم به آن اشاره می‌کند.

در نتیجه، ارسال ارجاع یک شیء به تابع می‌تواند نوعی Aliasing ایجاد کند. اگر تابع آن شیء را تغییر دهد، تغییرات پس از پایان اجرای تابع نیز باقی می‌مانند.

**نکتهٔ مهم:** ارسال لیست به تابع به این معنا نیست که خود متغیر فراخواننده با هر نوع تغییری در پارامتر تابع تغییر می‌کند. آنچه در این مثال تغییر کرده، خود شیء لیست است؛ نه اتصال متغیر `letters` به آن شیء.
