## بازگشت بی‌نهایت (Infinite Recursion)

اگر یک تابع بازگشتی هیچ‌وقت به حالت پایه (Base Case) نرسد، فراخوانی‌های بازگشتی همین‌طور ادامه پیدا می‌کنند و برنامه هیچ‌وقت به پایان نمی‌رسد. به این وضعیت **Infinite Recursion** یا بازگشت بی‌نهایت می‌گوییم.

برای مثال، تابع زیر را در نظر بگیر:

!!! example "Python"

    ```python
    def recurse():
        recurse()
    ```

هر بار که تابع `recurse` اجرا می‌شود، دوباره خودش را فراخوانی می‌کند. هر فراخوانی جدید نیز یک Frame جدید در Call Stack ایجاد می‌کند.

اما در پایتون تعداد Frameهایی که می‌توانند هم‌زمان روی Stack قرار بگیرند محدود است. اگر تعداد فراخوانی‌های بازگشتی از این محدودیت عبور کند، برنامه با یک Runtime Error مواجه می‌شود.

برای مثال، اگر تابع بالا را اجرا کنیم:

!!! example "Python"

    ```python
    recurse()
    ```

    **Output:**

    ```text
    RecursionError: maximum recursion depth exceeded
    ```

همان‌طور که در Traceback می‌بینی، خطا از نوع `RecursionError` است. در این مثال، هنگام وقوع خطا تقریباً سه هزار Frame در Stack ایجاد شده بود.

اگر به‌صورت تصادفی با Infinite Recursion مواجه شدی، تابع خودت را بررسی کن و به دو سؤال مهم پاسخ بده:

1. آیا تابع یک Base Case دارد که در آن دیگر فراخوانی بازگشتی انجام نمی‌شود؟
    
2. اگر Base Case وجود دارد، آیا مطمئن هستی که اجرای تابع در نهایت به آن می‌رسد؟
    

وجود Base Case به‌تنهایی کافی نیست؛ باید مطمئن باشیم که شرایط اجرای تابع واقعاً به سمت رسیدن به آن پیش می‌روند.

## دریافت ورودی از کاربر (Keyboard Input)

تا اینجا برنامه‌هایی که نوشته‌ایم، هیچ ورودی‌ای از کاربر دریافت نمی‌کردند. یعنی هر بار که اجرا می‌شدند، همان کارهای قبلی را با همان مقادیر انجام می‌دادند.

اما چطور می‌توانیم برنامه‌ای بنویسیم که هنگام اجرا از کاربر اطلاعات بگیرد؟

پایتون یک تابع داخلی به نام `input()` دارد. این تابع اجرای برنامه را متوقف می‌کند و منتظر می‌ماند تا کاربر چیزی وارد کند.

به‌محض اینکه کاربر کلید `Enter` را فشار دهد، اجرای برنامه ادامه پیدا می‌کند و تابع `input()` مقداری را که کاربر وارد کرده است، به‌صورت یک String برمی‌گرداند.

!!! example "Python"

    ```python
    text = input()
    ```

در این مثال، برنامه منتظر می‌ماند تا کاربر ورودی‌ای وارد کند. سپس مقدار واردشده به متغیر `text` اختصاص داده می‌شود.

### نمایش پیام قبل از دریافت ورودی

معمولاً بهتر است قبل از دریافت ورودی، به کاربر بگوییم چه چیزی باید وارد کند.

تابع `input()` می‌تواند یک Prompt به‌عنوان Argument دریافت کند:

!!! example "Python"

    ```python
    name = input('What...is your name?\n')
    name
    ```

    **Output:**

    ```text
    What...is your name?
    It is Arthur, King of the Britons

    'It is Arthur, King of the Britons'
    ```

در این مثال، عبارت `What...is your name?` به کاربر نمایش داده می‌شود و برنامه منتظر می‌ماند تا او پاسخش را وارد کند.

اما یک نکته کوچک در انتهای Prompt وجود دارد:

```
\n
```

این توالی را **Newline** می‌نامیم. در واقع، `\n` یک کاراکتر ویژه است که باعث ایجاد خط جدید می‌شود.

به همین دلیل، ورودی کاربر در خط بعد از پیام نمایش داده می‌شود، نه در ادامه همان خط.

### تبدیل ورودی به عدد صحیح

یک نکته مهم درباره `input()` وجود دارد: این تابع همیشه ورودی کاربر را به‌صورت String برمی‌گرداند؛ حتی اگر کاربر یک عدد وارد کرده باشد!

فرض کن انتظار داریم کاربر یک عدد صحیح وارد کند. در این صورت می‌توانیم از تابع `int()` برای تبدیل مقدار دریافتی به Integer استفاده کنیم.

!!! example "Python"

    ```python
    prompt = 'What...is the airspeed velocity of an unladen swallow?\n'
    speed = input(prompt)
    speed
    ```

    **Output:**

    ```text
    What...is the airspeed velocity of an unladen swallow?
    What do you mean: an African or European swallow?

    'What do you mean: an African or European swallow?'
    ```

در این مثال، کاربر به‌جای یک عدد، یک جمله وارد کرده است. حالا اگر بخواهیم مقدار `speed` را به عدد صحیح تبدیل کنیم، چه اتفاقی می‌افتد؟

!!! example "Python"

    ```python
    int(speed)
    ```

    **Output:**

    ```text
    ValueError: invalid literal for int() with base 10: 'What do you mean: an African or European swallow?'
    ```

همان‌طور که می‌بینی، پایتون نمی‌تواند این String را به یک عدد صحیح تبدیل کند؛ بنابراین خطای `ValueError` رخ می‌دهد.

بعداً یاد می‌گیریم چطور چنین خطاهایی را مدیریت کنیم تا برنامه به‌جای متوقف‌شدن، بتواند به شکل مناسبی به ورودی نامعتبر کاربر واکنش نشان دهد.

## اشکال‌زدایی (Debugging)

وقتی در برنامه با Syntax Error یا Runtime Error مواجه می‌شویم، پایتون پیامی نمایش می‌دهد که اطلاعات زیادی درباره خطا در اختیارمان قرار می‌دهد.

البته این اطلاعات گاهی ممکن است گیج‌کننده باشند. معمولاً مهم‌ترین بخش‌های یک پیام خطا عبارت‌اند از:

- **نوع خطا (Error Type):** چه نوع خطایی رخ داده است؟
    
- **محل وقوع خطا (Error Location):** خطا در کدام قسمت برنامه شناسایی شده است؟
    

خطاهای Syntax معمولاً پیدا کردنشان ساده است، اما گاهی نکات ظریفی وجود دارد که کار را دشوار می‌کند.

یکی از این موارد، خطاهای مربوط به فاصله‌ها و Tabها است. مشکل اینجاست که این کاراکترها همیشه به‌صورت واضح دیده نمی‌شوند و معمولاً هنگام خواندن کد به آن‌ها توجه نمی‌کنیم.

برای مثال:

!!! example "Python"

    ```python
    x = 5
     y = 6
    ```

    **Output:**

    ```text
    IndentationError: unexpected indent
    ```

در این مثال، خط دوم به‌اشتباه با یک فاصله اضافی شروع شده است. پایتون انتظار ندارد این خط در چنین موقعیتی دارای تورفتگی باشد.

نکته جالب اینجاست که پیام خطا به متغیر `y` اشاره می‌کند؛ اما این موضوع ممکن است کمی گمراه‌کننده باشد.

در واقع، پیام‌های خطا معمولاً محل شناسایی مشکل را نشان می‌دهند، نه لزوماً محل واقعی ایجاد آن را. بنابراین ممکن است مشکل از خطی قبل‌تر از خطی باشد که در پیام خطا مشخص شده است.

این موضوع فقط به Syntax Error محدود نمی‌شود و در Runtime Errorها هم ممکن است اتفاق بیفتد.

### پیدا کردن علت واقعی Runtime Error

فرض کن می‌خواهیم یک نسبت (Ratio) را به واحد دسی‌بل (Decibel) تبدیل کنیم. برای این کار، کد زیر را نوشته‌ایم:

!!! example "Python"

    ```python
    import math

    numerator = 9
    denominator = 10

    ratio = numerator // denominator
    decibels = 10 * math.log10(ratio)
    ```

    **Output:**

    ```text
    ValueError: math domain error
    ```

پیام خطا به خط پنجم اشاره می‌کند:

```
decibels = 10 * math.log10(ratio)
```

اما آیا واقعاً مشکلی در همین خط وجود دارد؟

برای پیدا کردن علت، باید کمی عقب‌تر برویم و مقدار متغیرها را بررسی کنیم.

در خط قبل، مقدار `ratio` را این‌طور محاسبه کرده‌ایم:

```
ratio = numerator // denominator
```

اینجا یک اشتباه کوچک اما مهم وجود دارد: به‌جای تقسیم اعشاری (`/`)، از تقسیم صحیح رو به پایین (`//`) استفاده کرده‌ایم.

بیایید مقدار محاسبه‌شده را بررسی کنیم:

```
ratio = 9 // 10
```

نتیجه برابر با `0` است؛ چون حاصل تقسیم `9` بر `10` برابر با `0.9` است و عملگر `//` آن را به سمت پایین گرد می‌کند.

حالا به خط بعد برگردیم:

```
math.log10(0)
```

تابع `math.log10()` لگاریتم بر پایه ۱۰ را محاسبه می‌کند. اما لگاریتم صفر تعریف نشده است؛ بنابراین صفر خارج از Domain یا دامنه مقادیر معتبر این تابع قرار دارد و پایتون خطای زیر را ایجاد می‌کند:

```
ValueError: math domain error
```

پس مشکل واقعی از خط محاسبه `ratio` شروع شده بود، نه از خطی که خطا در آن گزارش شده است.

برای اصلاح برنامه کافی است از تقسیم معمولی استفاده کنیم:

!!! example "Python"

    ```python
    import math

    numerator = 9
    denominator = 10

    ratio = numerator / denominator
    decibels = 10 * math.log10(ratio)
    ```

    **Output:**

    ```text
    -0.4575749056067512
    ```

این بار مقدار `ratio` برابر با `0.9` است و تابع `math.log10()` می‌تواند آن را محاسبه کند.

در نهایت، هنگام Debugging همیشه پیام خطا را با دقت بخوان؛ اما هرگز فرض نکن که تمام اطلاعات آن دقیقاً به محل اصلی ایجاد مشکل اشاره می‌کنند.

گاهی باید چند خط به عقب برگردی، مقادیر متغیرها را بررسی کنی و مسیر اجرای برنامه را دنبال کنی تا علت واقعی خطا را پیدا کنی.
