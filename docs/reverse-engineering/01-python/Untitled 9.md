### تکمیل تابع distance

نتیجه‌ای که در مرحله قبل محاسبه کردیم درست بود؛ اما یک مشکل کوچک داشت: تابع به‌جای اینکه نتیجه را برگرداند، آن را با `print()` نمایش می‌داد. در نتیجه، مقدار بازگشتی تابع همچنان `None` بود.

برای اصلاح این موضوع، کافی است `print()` را با `return` جایگزین کنیم:

!!! example "Python"

````
```python
def distance(x1, y1, x2, y2):
    dx = x2 - x1
    dy = y2 - y1
    dsquared = dx**2 + dy**2
    result = math.sqrt(dsquared)
    return result
```
````

حالا تابع `distance` یک **Pure Function** است؛ یعنی نتیجه را برمی‌گرداند، اما چیزی را مستقیماً نمایش نمی‌دهد یا اثر جانبی دیگری ایجاد نمی‌کند.

اگر آن را مستقیماً فراخوانی کنیم، Jupyter مقدار بازگشتی را نمایش می‌دهد:

!!! example "Python"

````
```python
distance(1, 2, 4, 6)
```

**Output:**

```text
5.0
```
````

اما اگر نتیجه را در یک متغیر ذخیره کنیم، چیزی نمایش داده نمی‌شود:

```
d = distance(1, 2, 4, 6)
```

به همین سادگی!

### Scaffolding چیست؟

یادت هست در مراحل توسعه تابع `distance` از دستورهای `print()` برای بررسی مقادیر میانی مثل `dx`، `dy` و `dsquared` استفاده کردیم؟

این دستورها هنگام Debugging بسیار مفید بودند؛ چون به ما کمک می‌کردند مطمئن شویم هر مرحله از محاسبات درست انجام می‌شود.

اما حالا که تابع به‌درستی کار می‌کند، دیگر نیازی به آن‌ها نداریم و می‌توانیم حذفشان کنیم.

به کدهایی که در فرایند ساخت و توسعه برنامه به ما کمک می‌کنند، اما جزئی از محصول نهایی نیستند، **Scaffolding** می‌گوییم.

در واقع، Scaffolding مثل داربستی است که هنگام ساخت یک ساختمان از آن استفاده می‌کنیم؛ وقتی کار تمام شد، دیگر نیازی به آن نداریم.

مثال تابع `distance` سه اصل مهم در Incremental Development را نشان می‌دهد:

1. کار را با یک برنامه قابل اجرا شروع کن، تغییرات کوچک ایجاد کن و بعد از هر تغییر برنامه را آزمایش کن.
    
2. برای نگهداری مقادیر میانی از متغیرها استفاده کن تا بتوانی آن‌ها را نمایش دهی و بررسی کنی.
    
3. وقتی برنامه به‌درستی کار کرد، کدهای موقتی و اضافی (Scaffolding) را حذف کن.
    

با این روش، اگر در هر مرحله خطایی رخ دهد، معمولاً می‌دانیم باید دنبال مشکل کجا بگردیم.

Incremental Development می‌تواند زمان زیادی از Debugging را برایمان ذخیره کند.

## توابع بولی (Boolean Functions)

تابع‌ها می‌توانند مقادیر بولی، یعنی `True` و `False` را نیز برگردانند.

این قابلیت زمانی بسیار کاربردی است که بخواهیم یک شرط یا بررسی نسبتاً پیچیده را داخل یک تابع قرار دهیم و نتیجه آن را به‌صورت یک مقدار بولی دریافت کنیم.

برای مثال، فرض کن می‌خواهیم بررسی کنیم آیا عدد `x` بر عدد `y` بخش‌پذیر است یا نه؛ یعنی باقی‌مانده تقسیم آن‌ها صفر باشد.

می‌توانیم تابعی به نام `is_divisible` بنویسیم:

!!! example "Python"

````
```python
def is_divisible(x, y):
    if x % y == 0:
        return True
    else:
        return False
```
````

در این تابع، از عملگر `%` برای محاسبه باقی‌مانده تقسیم استفاده می‌کنیم.

اگر باقی‌مانده صفر باشد، مقدار `True` برمی‌گردد؛ در غیر این صورت، مقدار `False` برگردانده می‌شود.

حالا تابع را با چند مقدار مختلف آزمایش کنیم:

!!! example "Python"

````
```python
is_divisible(6, 4)
```

**Output:**

```text
False
```
````

چون عدد ۶ بر ۴ بدون باقی‌مانده بخش‌پذیر نیست.

!!! example "Python"

````
```python
is_divisible(6, 3)
```

**Output:**

```text
True
```
````

این بار باقی‌مانده تقسیم صفر است؛ بنابراین نتیجه `True` خواهد بود.

### ساده‌تر کردن Boolean Function

اما می‌توانیم این تابع را کوتاه‌تر هم بنویسیم.

به عبارت زیر دقت کن:

```
x % y == 0
```

نتیجه عملگر `==` خودش یک مقدار بولی است؛ یعنی یا `True` برمی‌گرداند یا `False`.

پس چه نیازی داریم دوباره با `if` بررسی کنیم که نتیجه `True` است یا `False` و سپس همان مقدار را برگردانیم؟

می‌توانیم مستقیماً نتیجه Expression را با `return` برگردانیم:

!!! example "Python"

````
```python
def is_divisible(x, y):
    return x % y == 0
```
````

این نسخه دقیقاً همان رفتار نسخه قبلی را دارد، اما ساده‌تر و خواناتر است.

### استفاده از Boolean Function در شرط‌ها

توابع بولی معمولاً در دستورهای شرطی هم استفاده می‌شوند.

برای مثال:

!!! example "Python"

````
```python
if is_divisible(6, 2):
    print('divisible')
```

**Output:**

```text
divisible
```
````

تابع `is_divisible(6, 2)` مقدار `True` را برمی‌گرداند؛ بنابراین بدنه دستور `if` اجرا می‌شود.

ممکن است وسوسه شوی شرط را به این شکل بنویسی:

```
if is_divisible(6, 2) == True:
    print('divisible')
```

اما این مقایسه اضافی است!

چرا؟ چون خود تابع از قبل یک مقدار بولی برمی‌گرداند. بنابراین می‌توانیم مستقیماً از نتیجه آن در شرط `if` استفاده کنیم.

## بازگشت همراه با مقادیر بازگشتی (Recursion with Return Values)

تا اینجا یاد گرفتیم چطور توابعی بنویسیم که مقدار برمی‌گردانند. حالا می‌توانیم این قابلیت را با Recursion ترکیب کنیم و توابع بازگشتی‌ای بنویسیم که نتیجه محاسباتشان را برمی‌گردانند.

این مرحله اهمیت زیادی دارد؛ چون با ترکیب این مفاهیم، به نقطه مهمی در توانایی‌های برنامه‌نویسی‌مان می‌رسیم.

مجموعه قابلیت‌هایی از پایتون که تا اینجا یاد گرفته‌ایم، از نظر محاسباتی **Turing Complete** است. یعنی می‌توانیم هر محاسبه‌ای را که توسط یک الگوریتم قابل توصیف باشد، با این قابلیت‌ها پیاده‌سازی کنیم.

برای درک بهتر Recursion همراه با Return Value، چند تابع ریاضی را که به‌صورت بازگشتی تعریف می‌شوند بررسی می‌کنیم.

### تعریف بازگشتی چیست؟

یک تعریف بازگشتی (Recursive Definition) تا حدی شبیه یک تعریف دوری است؛ چون چیزی که در حال تعریف آن هستیم، در خود تعریف هم ظاهر می‌شود.

البته یک تعریف کاملاً دوری معمولاً چندان مفید نیست!

برای مثال، فرض کن در یک فرهنگ لغت چنین تعریفی ببینی:

> Vorpal: صفتی برای توصیف چیزی که Vorpal است!

احتمالاً با خواندن چنین تعریفی چیزی یاد نمی‌گیری؛ چون کلمه‌ای که قرار بوده توضیح داده شود، دوباره در تعریف خودش استفاده شده است.

اما همه تعریف‌های بازگشتی بی‌فایده نیستند. بعضی از آن‌ها بسیار دقیق و کاربردی‌اند.

برای مثال، تابع فاکتوریل (Factorial) را در نظر بگیر که با علامت `!` نمایش داده می‌شود.

تعریف ریاضی آن به شکل زیر است:

[  
0! = 1  
]

[  
n! = n \times (n-1)!  
]

این تعریف دو بخش دارد:

1. فاکتوریل صفر برابر با یک است.
    
2. فاکتوریل هر عدد دیگر، برابر است با حاصل‌ضرب آن عدد در فاکتوریل عدد قبل از آن.
    

برای مثال:

[  
3! = 3 \times 2!  
]

و:

[  
2! = 2 \times 1!  
]

همچنین:

[  
1! = 1 \times 0!  
]

از آنجا که می‌دانیم:

[  
0! = 1  
]

می‌توانیم محاسبات را به عقب برگردانیم:

[  
1! = 1 \times 1 = 1  
]

[  
2! = 2 \times 1 = 2  
]

[  
3! = 3 \times 2 = 6  
]

حالا سؤال این است: اگر بتوانیم چیزی را به‌صورت بازگشتی تعریف کنیم، آیا می‌توانیم برنامه‌ای بنویسیم که همان تعریف را محاسبه کند؟

بله! دقیقاً همین کار را انجام می‌دهیم.

### پیاده‌سازی Factorial با Incremental Development

مثل مثال‌های قبلی، این بار هم از روش توسعه تدریجی استفاده می‌کنیم.

ابتدا تابعی می‌نویسیم که یک پارامتر به نام `n` دریافت کند و فعلاً همیشه مقدار صفر را برگرداند:

!!! example "Python"

````
```python
def factorial(n):
    return 0
```
````

هنوز هیچ محاسبه‌ای انجام نمی‌دهیم؛ فقط ساختار اولیه تابع را آماده کرده‌ایم.

حالا بخش اول تعریف ریاضی را پیاده‌سازی می‌کنیم:

اگر مقدار `n` برابر با صفر باشد، باید مقدار یک را برگردانیم.

!!! example "Python"

````
```python
def factorial(n):
    if n == 0:
        return 1
    else:
        return 0
```
````

تا اینجا حالت پایه (Base Case) را پیاده‌سازی کرده‌ایم.

اما برای مقادیر دیگر چه کاری باید انجام دهیم؟

طبق تعریف ریاضی، باید فاکتوریل `n - 1` را محاسبه کنیم و نتیجه را در `n` ضرب کنیم.

برای این کار، تابع را به‌صورت بازگشتی فراخوانی می‌کنیم:

!!! example "Python"

````
```python
def factorial(n):
    if n == 0:
        return 1
    else:
        recurse = factorial(n - 1)
        return n * recurse
```
````

حالا تابع ما هر دو بخش تعریف ریاضی فاکتوریل را پیاده‌سازی می‌کند:

- اگر `n` برابر با صفر باشد، مقدار `1` برگردانده می‌شود.
    
- در غیر این صورت، ابتدا `factorial(n - 1)` محاسبه می‌شود و سپس نتیجه در `n` ضرب می‌شود.
    

### دنبال کردن اجرای تابع factorial

بیایید ببینیم اگر تابع را با مقدار `3` فراخوانی کنیم، چه اتفاقی می‌افتد.

!!! example "Python"

````
```python
factorial(3)
```
````

اجرای تابع را مرحله‌به‌مرحله دنبال کنیم:

1. مقدار `3` با صفر برابر نیست؛ پس وارد شاخه `else` می‌شویم و باید `factorial(2)` را محاسبه کنیم.
    
2. مقدار `2` هم صفر نیست؛ بنابراین فراخوانی بعدی `factorial(1)` خواهد بود.
    
3. مقدار `1` نیز صفر نیست؛ پس تابع دوباره خودش را با مقدار `0` فراخوانی می‌کند.
    
4. این بار `n == 0` برقرار است. تابع مقدار `1` را برمی‌گرداند و دیگر هیچ فراخوانی بازگشتی انجام نمی‌شود.
    

حالا بخش بازگشت (Unwinding) آغاز می‌شود؛ یعنی نتایج به‌ترتیب به فراخوانی‌های قبلی برمی‌گردند:

- فراخوانی مربوط به `n = 1` مقدار `1` را از فراخوانی داخلی دریافت می‌کند و محاسبه می‌کند:
    
    [  
    1 \times 1 = 1  
    ]
    
- فراخوانی مربوط به `n = 2` مقدار `1` را دریافت می‌کند و محاسبه می‌کند:
    
    [  
    2 \times 1 = 2  
    ]
    
- در نهایت، فراخوانی اولیه با `n = 3` مقدار `2` را دریافت می‌کند و محاسبه می‌کند:
    
    [  
    3 \times 2 = 6  
    ]
    

پس نتیجه نهایی برابر با `6` است.

**Output:**

```
6
```

در واقع، هر فراخوانی بازگشتی منتظر می‌ماند تا فراخوانی داخلی نتیجه‌اش را برگرداند. سپس از آن نتیجه برای ادامه محاسبات خودش استفاده می‌کند.

### Stack Diagram در تابع factorial

در نمودار Stack مربوط به این اجرا، هر Frame مقدار متفاوتی از `n` را نگه می‌دارد:

- `n = 3`
    
- `n = 2`
    
- `n = 1`
    
- `n = 0`
    

مقادیر بازگشتی نیز از پایین Stack به سمت بالا منتقل می‌شوند.

در هر Frame، مقدار بازگشتی حاصل‌ضرب `n` در متغیر محلی `recurse` است.

یک نکته ظریف هم وجود دارد: در آخرین Frame، یعنی جایی که `n = 0` است، متغیر محلی `recurse` اصلاً ایجاد نمی‌شود؛ چون شاخه‌ای که این متغیر را تعریف می‌کند (`else`) اجرا نشده است.

این مثال نشان می‌دهد که Recursion فقط برای تکرار یک عملیات نیست؛ می‌توانیم نتایج محاسبات را از فراخوانی‌های داخلی دریافت کنیم و مرحله‌به‌مرحله به نتیجه نهایی برسیم.
