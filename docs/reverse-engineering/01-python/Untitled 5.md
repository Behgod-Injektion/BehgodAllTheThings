## شرط‌های تو در تو (Nested Conditionals)

می‌توانیم یک شرط را داخل شرط دیگری قرار دهیم. به این ساختار، **Nested Conditional** یا شرط تو در تو می‌گوییم.

برای مثال، شرطی را که در بخش قبل بررسی کردیم، می‌توانیم به شکل زیر هم بنویسیم:

!!! example "Python"

    ```python
    if x == y:
        print('x and y are equal')
    else:
        if x < y:
            print('x is less than y')
        else:
            print('x is greater than y')
    ```

    **Output:**

    ```text
    x is less than y
    ```

در این مثال، شرط بیرونی (`if`) دو شاخه دارد:

- شاخه اول، فقط یک دستور ساده دارد.
    
- شاخه دوم، خودش شامل یک دستور `if` دیگر است که دو شاخه جداگانه دارد.
    

هر دو شاخه شرط داخلی نیز دستورهای ساده‌ای هستند؛ البته هیچ محدودیتی وجود ندارد که آن‌ها هم شامل شرط‌های دیگری باشند!

اگر به تورفتگی‌ها (Indentation) دقت کنیم، ساختار شرط‌های تو در تو کاملاً مشخص است. با این حال، وقتی تعداد این شرط‌ها زیاد شود، خواندن و درک کد دشوارتر خواهد شد. به همین دلیل بهتر است تا جای ممکن از شرط‌های تو در تو دوری کنیم.

گاهی می‌توانیم با استفاده از **Logical Operators**، ساختار شرط‌های تو در تو را ساده‌تر کنیم.

فرض کن می‌خواهیم بررسی کنیم که آیا مقدار `x` یک عدد مثبت و تک‌رقمی است یا نه. می‌توانیم این کار را با دو شرط تو در تو انجام دهیم:

!!! example "Python"

    ```python
    if 0 < x:
        if x < 10:
            print('x is a positive single-digit number.')
    ```

    **Output:**

    ```text
    x is a positive single-digit number.
    ```

دستور `print` فقط زمانی اجرا می‌شود که هر دو شرط برقرار باشند:

1. مقدار `x` بزرگ‌تر از صفر باشد.
    
2. مقدار `x` کوچک‌تر از ۱۰ باشد.
    

پس می‌توانیم همین منطق را با استفاده از عملگر `and` و بدون نیاز به شرط تو در تو پیاده‌سازی کنیم:

!!! example "Python"

    ```python
    if 0 < x and x < 10:
        print('x is a positive single-digit number.')
    ```

    **Output:**

    ```text
    x is a positive single-digit number.
    ```

اما صبر کن! پایتون برای چنین شرایطی یک روش حتی خلاصه‌تر هم دارد: **Chained Comparisons** یا مقایسه‌های زنجیره‌ای.

```
if 0 < x < 10:
    print('x is a positive single-digit number.')
```

این عبارت دقیقاً همان معنی دو مقایسه‌ای را دارد که با `and` به هم متصل شده‌اند. یعنی مقدار `x` باید هم‌زمان بزرگ‌تر از صفر و کوچک‌تر از ۱۰ باشد.

به همین سادگی، بدون شرط تو در تو و بدون نوشتن چندباره نام متغیر!

## بازگشت (Recursion)

یکی از قابلیت‌های جالب در برنامه‌نویسی این است که یک Function می‌تواند خودش را فراخوانی کند!

شاید در نگاه اول مشخص نباشد چرا باید یک تابع خودش را صدا بزند؛ اما این قابلیت یکی از ابزارهای قدرتمند برنامه‌نویسی است و به آن **Recursion** یا بازگشت می‌گوییم.

برای شروع، تابع ساده‌ای می‌نویسیم که از یک عدد به سمت صفر شمارش معکوس انجام دهد:

!!! example "Python"

    ```python
    def countdown(n):
        if n <= 0:
            print('Blastoff!')
        else:
            print(n)
            countdown(n - 1)
    ```

در این تابع، ابتدا بررسی می‌کنیم که آیا `n` کوچک‌تر یا مساوی صفر است یا نه.

- اگر شرط برقرار باشد، عبارت `Blastoff!` چاپ می‌شود.
    
- در غیر این صورت، مقدار `n` چاپ شده و تابع دوباره خودش را فراخوانی می‌کند؛ با این تفاوت که این بار مقدار `n - 1` را به‌عنوان Argument دریافت می‌کند.
    

حالا ببینیم اگر این تابع را با مقدار `3` فراخوانی کنیم، چه اتفاقی می‌افتد:

!!! example "Python"

    ```python
    countdown(3)
    ```

    **Output:**

    ```text
    3
    2
    1
    Blastoff!
    ```

بیایید اجرای برنامه را مرحله‌به‌مرحله دنبال کنیم:

1. اجرای `countdown` با `n = 3` آغاز می‌شود. چون `n` بزرگ‌تر از صفر است، مقدار `3` چاپ می‌شود و تابع خودش را با مقدار `2` فراخوانی می‌کند.
    
2. حالا اجرای جدیدی از `countdown` با `n = 2` آغاز می‌شود. دوباره شرط برقرار است؛ پس `2` چاپ شده و تابع با مقدار `1` خودش را فراخوانی می‌کند.
    
3. اجرای بعدی با `n = 1` شروع می‌شود. مقدار `1` چاپ شده و تابع با مقدار `0` فراخوانی می‌شود.
    
4. این بار اجرای تابع با `n = 0` آغاز می‌شود. شرط `n <= 0` برقرار است؛ بنابراین `Blastoff!` چاپ می‌شود و این فراخوانی از تابع به پایان می‌رسد.
    
5. حالا فراخوانی‌ای که با `n = 1` اجرا شده بود، به پایان می‌رسد.
    
6. سپس فراخوانی مربوط به `n = 2` تمام می‌شود.
    
7. در نهایت، فراخوانی اولیه با `n = 3` نیز به پایان می‌رسد.
    

دقت کن که هر بار فراخوانی تابع، اجرای جدیدی از آن ایجاد می‌شود. این اجراها مستقل از یکدیگر نیستند؛ بلکه تا زمانی که فراخوانی داخلی تمام نشده باشد، فراخوانی قبلی منتظر می‌ماند.

## یک مثال دیگر از Recursion

حالا تابع دیگری می‌نویسیم که یک String را به تعداد مشخصی چاپ کند:

!!! example "Python"

    ```python
    def print_n_times(string, n):
        if n > 0:
            print(string)
            print_n_times(string, n - 1)
    ```

منطق تابع ساده است:

- اگر `n` بزرگ‌تر از صفر باشد، مقدار `string` چاپ می‌شود و تابع خودش را با همان `string` و مقدار `n - 1` فراخوانی می‌کند.
    
- اگر `n` صفر یا منفی باشد، شرط برقرار نیست و تابع هیچ کاری انجام نمی‌دهد.
    

برای مثال:

!!! example "Python"

    ```python
    print_n_times('Spam ', 4)
    ```

    **Output:**

    ```text
    Spam
    Spam
    Spam
    Spam
    ```

البته برای مثال ساده‌ای مثل این، احتمالاً استفاده از یک `for` loop راحت‌تر است. اما جلوتر با مسائلی روبه‌رو می‌شویم که پیاده‌سازی آن‌ها با حلقه دشوار است، در حالی که با Recursion می‌توانیم راه‌حل ساده‌تری برایشان بنویسیم.

به همین دلیل بهتر است از همین ابتدا با مفهوم بازگشت آشنا شویم.

## Stack Diagram در توابع بازگشتی

حالا که فهمیدیم یک تابع چگونه می‌تواند خودش را فراخوانی کند، بیایید ببینیم این اتفاق در Call Stack چه تأثیری دارد.

فرض کن تابع `countdown` را با مقدار `3` اجرا کرده‌ایم. در این حالت، چهار فراخوانی از تابع ایجاد می‌شود و هرکدام Frame مخصوص به خودش را در Stack دارند:

- Frame اول مربوط به `n = 3` است.
    
- Frame دوم مربوط به `n = 2` است.
    
- Frame سوم مربوط به `n = 1` است.
    
- Frame چهارم مربوط به `n = 0` است.
    

هر Frame مقدار مستقلی از پارامتر `n` را نگه می‌دارد؛ بنابراین تغییر مقدار `n` در یک فراخوانی، مقدار آن را در Frameهای دیگر تغییر نمی‌دهد.

به آخرین فراخوانی، یعنی جایی که `n = 0` است، **Base Case** یا حالت پایه می‌گوییم.

چرا این فراخوانی را حالت پایه می‌نامیم؟

چون در این مرحله دیگر تابع خودش را فراخوانی نمی‌کند. در نتیجه Frame جدیدی به Stack اضافه نمی‌شود و زنجیره فراخوانی‌های بازگشتی متوقف می‌شود.

پس از پایان Base Case، اجرای برنامه به‌ترتیب به فراخوانی‌های قبلی برمی‌گردد تا همه آن‌ها نیز تمام شوند.
