## جایگزینی رشته‌ها با Regex (String Substitution)

همان‌طور که می‌دانیم، Bram Stoker در ایرلند متولد شد و زمانی که رمان Dracula در سال ۱۸۹۷ منتشر شد، در انگلستان زندگی می‌کرد.

بنابراین انتظار داریم در نوشته‌هایش از املای بریتانیایی کلماتی مثل `centre` و `colour` استفاده کرده باشد، نه شکل آمریکایی آن‌ها یعنی `center` و `color`.

برای بررسی این موضوع، می‌توانیم از یک الگوی Regex استفاده کنیم که هر دو شکل `centre` و `center` را تشخیص دهد:

```
pattern = 'cent(er|re)'
```

شاید بپرسی چرا این بار از پرانتز استفاده کرده‌ایم؟

پرانتزها مشخص می‌کنند که عملگر `|` باید روی کدام بخش از الگو اعمال شود.

در این مثال، عبارت `er|re` یعنی یکی از دو حالت `er` یا `re` باید در آن موقعیت قرار بگیرد.

پس الگوی `cent(er|re)` به دنبال رشته‌ای می‌گردد که با `cent` شروع شود و پس از آن یکی از دو دنباله `er` یا `re` قرار گرفته باشد.

در نتیجه، هر دو کلمه زیر با این الگو مطابقت دارند:

```
center
centre
```

حالا می‌توانیم اولین موردی را که با این الگو مطابقت دارد در کتاب پیدا کنیم:

```
result = find_first(pattern)
result.string
```

خروجی:

```
'horseshoe of the Carpathians, as if it were the centre of some sort of\n'
```

همان‌طور که می‌بینی، شکل بریتانیایی کلمه، یعنی `centre`، در متن استفاده شده است.

### کاراکتر ? و اختیاری‌بودن یک کاراکتر

حالا می‌خواهیم همین بررسی را برای کلمه `colour` انجام دهیم.

در اینجا می‌توانیم از یک کاراکتر ویژه دیگر در Regex استفاده کنیم: `?`

این کاراکتر مشخص می‌کند که بخش بلافاصله قبل از آن اختیاری است؛ یعنی آن بخش می‌تواند وجود داشته باشد یا نداشته باشد.

برای مثال:

```
pattern = 'colou?r'
```

در این الگو، علامت `?` بعد از `u` قرار گرفته است. بنابراین وجود حرف `u` اختیاری خواهد بود.

در نتیجه، الگوی ما هر دو شکل زیر را تشخیص می‌دهد:

```
colour
color
```

حالا اولین خطی را پیدا کنیم که با این الگو مطابقت دارد:

```
result = find_first(pattern)
line = result.string
line
```

خروجی:

```
'undergarment with long double apron, front, and back, of coloured stuff\n'
```

باز هم مشخص شد که Stoker از املای بریتانیایی استفاده کرده است.

### استفاده از re.sub() برای جایگزینی

حالا فرض کن می‌خواهیم نسخه‌ای از کتاب تهیه کنیم که در آن املای بریتانیایی به شکل آمریکایی تبدیل شده باشد.

برای این کار، ماژول `re` تابعی به نام `sub()` در اختیارمان قرار می‌دهد.

این تابع برای جایگزین‌کردن بخش‌هایی از یک رشته که با الگوی مشخصی مطابقت دارند، استفاده می‌شود.

مثلاً:

```
re.sub(pattern, 'color', line)
```

خروجی:

```
'undergarment with long double apron, front, and back, of colored stuff\n'
```

تابع `sub()` در این مثال سه آرگومان دریافت می‌کند:

1. **الگو (Pattern):** عبارتی که می‌خواهیم در متن پیدا کنیم.
    
2. **رشته جایگزین (Replacement):** عبارتی که قرار است جایگزین تطبیق پیدا شده شود.
    
3. **رشته ورودی (String):** متنی که می‌خواهیم در آن جست‌وجو و جایگزینی انجام دهیم.
    

پس در این مثال، هر بخشی از `line` که با الگوی `colou?r` مطابقت داشته باشد، با `color` جایگزین می‌شود.

نکته مهم این است که `sub()` هم مانند متدهای رشته‌ای که قبلاً دیدیم، رشته اصلی را تغییر نمی‌دهد؛ بلکه یک رشته جدید برمی‌گرداند.

## اشکال‌زدایی (Debugging)

هنگام خواندن و نوشتن فایل‌ها، پیدا کردن و رفع خطاها گاهی می‌تواند دشوار باشد؛ مخصوصاً زمانی که با فایل‌های بزرگ سروکار داریم.

اگر در محیط Jupyter Notebook کار می‌کنی، می‌توانی از بعضی دستورهای Shell برای بررسی سریع فایل‌ها کمک بگیری.

برای مثال، دستور `head` چند خط ابتدایی یک فایل را نمایش می‌دهد.

در Jupyter می‌توانیم آن را به این شکل اجرا کنیم:

```
!head pg345_cleaned.txt
```

علامت `!` در ابتدای دستور نشان می‌دهد که قرار نیست این دستور توسط Python اجرا شود؛ بلکه یک دستور Shell است که از داخل محیط Jupyter اجرا می‌شود.

به همین شکل، دستور `tail` چند خط انتهایی فایل را نمایش می‌دهد:

```
!tail pg345_cleaned.txt
```

این دو دستور هنگام بررسی فایل‌های متنی بسیار کاربردی هستند؛ چون لازم نیست برای دیدن ابتدای یا انتهای یک فایل بزرگ، تمام محتوای آن را چاپ کنیم.

### کار با بخشی از فایل هنگام اشکال‌زدایی

وقتی فایل بزرگی داریم، بررسی خروجی برنامه می‌تواند دشوار شود؛ چون ممکن است حجم زیادی از اطلاعات تولید شود و پیدا کردن مشکل در میان آن‌ها زمان‌بر باشد.

یک راهکار مناسب این است که ابتدا برنامه را روی بخش کوچکی از فایل آزمایش کنیم. وقتی مطمئن شدیم برنامه درست کار می‌کند، آن را روی کل فایل اجرا کنیم.

برای ساخت یک فایل کوچک از بخشی از فایل اصلی، می‌توانیم دوباره از دستور `head` استفاده کنیم؛ اما این بار خروجی آن را به‌جای نمایش در ترمینال، داخل یک فایل جدید ذخیره می‌کنیم.

برای این کار از عملگر `>` استفاده می‌شود که خروجی یک دستور را به فایل هدایت می‌کند.

```
!head pg345_cleaned.txt > pg345_cleaned_10_lines.txt
```

به‌صورت پیش‌فرض، دستور `head` ده خط اول فایل را می‌خواند. بنابراین دستور بالا ده خط ابتدایی فایل اصلی را در فایل جدیدی به نام `pg345_cleaned_10_lines.txt` ذخیره می‌کند.

اگر بخواهیم تعداد خطوط بیشتری را انتخاب کنیم، می‌توانیم تعداد موردنظر را به‌عنوان آرگومان به `head` بدهیم.

مثلاً برای ذخیره صد خط اول:

```
!head -100 pg345_cleaned.txt > pg345_cleaned_100_lines.txt
```

در این دستور:

- `head -100` صد خط ابتدایی فایل را انتخاب می‌کند.
    
- `>` خروجی دستور را به یک فایل هدایت می‌کند.
    
- `pg345_cleaned_100_lines.txt` نام فایل جدیدی است که خروجی در آن ذخیره می‌شود.
    

به این ترتیب، یک نسخه کوچک‌تر از فایل اصلی داریم که می‌توانیم برنامه‌مان را ابتدا روی آن آزمایش کنیم.

**یک نکته مهم:** دستورهای Shell مثل `head` و `tail` در همه سیستم‌عامل‌ها یا محیط‌ها در دسترس نیستند. اگر این دستورها روی سیستم تو کار نکردند، می‌توانیم عملیات مشابهی را مستقیماً با Python پیاده‌سازی کنیم.

هدف اصلی این روش ساده است: به‌جای اینکه از همان ابتدا با یک فایل بزرگ سروکله بزنیم، ابتدا روی داده‌های کوچک‌تر کار می‌کنیم، خطاها را پیدا می‌کنیم و بعد سراغ کل فایل می‌رویم.
