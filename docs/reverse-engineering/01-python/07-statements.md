## وارد کردن ماژول‌ها (The `import` Statement)

آیا تمام امکاناتی که برای برنامه‌نویسی نیاز داریم، از همان ابتدا در دسترس هستند؟

نه لزوماً! Python قابلیت‌های زیادی دارد که در قالب ماژول‌ها در اختیارمان قرار می‌گیرند. برای استفاده از این قابلیت‌ها، ابتدا باید ماژول موردنظر را وارد برنامه کنیم.

این کار با دستور `import` انجام می‌شود:


```python
import math
```


با اجرای این دستور، ماژول `math` در برنامه در دسترس قرار می‌گیرد. این ماژول مجموعه‌ای از قابلیت‌های ریاضی را فراهم می‌کند که می‌توانیم از آن‌ها استفاده کنیم.

### Module چیست؟

ماژول (Module) مجموعه‌ای از کدهای Python است که می‌تواند شامل متغیرها، توابع و کلاس‌ها باشد.

برای مثال، ماژول `math` شامل مقادیر و توابعی است که در محاسبات ریاضی کاربرد دارند:

- متغیرها و ثابت‌ها: `pi`، `e` و `tau`
    
- توابع: `sqrt()`، `pow()` و `ceil()`
    

می‌توانیم ساختار مفهومی آن را این‌طور در نظر بگیریم:

```
math
 ├── pi
 ├── e
 ├── tau
 ├── sqrt()
 ├── pow()
 └── ceil()
```

حالا چطور به این قابلیت‌ها دسترسی پیدا کنیم؟

!!! example "Python"

	
	```python
	import math
	
	print(math.pi)
	```
	
	**Output:**
	
	```text
	3.141592653589793
	```
	

اینجا با سه مفهوم روبه‌رو هستیم:

- `math` نام ماژولی است که وارد برنامه کرده‌ایم.
    
- `pi` یکی از Attributeهای این ماژول است.
    
- `.` برای دسترسی به Attributeهای یک Object استفاده می‌شود.
    

### Dot Operator چیست؟

علامت نقطه (`.`) را Dot Operator می‌نامیم. با استفاده از آن می‌توانیم به Attributeهای یک Object دسترسی پیدا کنیم.

```
math.pi
```

در مثال بالا، `math` یک ماژول است و `pi` یکی از Attributeهای آن محسوب می‌شود.

اما آیا Dot Operator فقط برای دسترسی به قابلیت‌های ماژول‌ها استفاده می‌شود؟

خیر! این عملگر برای دسترسی به Attributeهای سایر Objectها نیز کاربرد دارد. برای مثال، در کد زیر از آن برای دسترسی به متدهای یک Object رشته‌ای استفاده کرده‌ایم:

!!! example "Python"

	
	```python
	message = "Python"
	
	print(message.upper())
	print(message.lower())
	```
	
	**Output:**
	
	```text
	PYTHON
	python
	```
	

در اینجا با استفاده از Dot Operator به متدهای Object رشته دسترسی پیدا کرده‌ایم. (متد یا Method تابعی است که به یک Object تعلق دارد و از طریق آن Object فراخوانی می‌شود.)

!!! note "پس یادت باشد"
	Dot Operator برای دسترسی به Attributeهای یک Object استفاده می‌شود؛ فرقی نمی‌کند آن Object یک ماژول باشد یا یک رشته، عدد یا هر نوع Object دیگری.

### استفاده از توابع ماژول `math`

حالا که می‌دانیم چطور به قابلیت‌های یک ماژول دسترسی پیدا کنیم، بیایید چند تابع از `math` را بررسی کنیم.


!!! example "Python"

	
	```python
	import math
	
	print(math.sqrt(25))
	```
	
	**Output:**
	
	```text
	5.0
	```
	

تابع `sqrt()` جذر عدد را محاسبه می‌کند.


!!! example "Python"


	```python
	import math
	
	print(math.pow(5, 2))
	```
	
	**Output:**
	
	```text
	25.0
	```
	

این تابع عدد اول را به توان عدد دوم می‌رساند.

اما صبر کن! مگر برای محاسبه توان در Python عملگر `**` را نداریم؟

چرا، اتفاقاً می‌توانیم همان محاسبه را به شکل ساده‌تری انجام دهیم:

!!! example "Python"

	
	```python
	print(5 ** 2)
	print(5 ** -2)
	```
	
	**Output:**
	
	```text
	25
	0.04
	```
	

پس چرا خروجی این دو روش از نظر نوع داده متفاوت است؟

|روش|نتیجه|
|---|---|
|`math.pow(5, 2)`|`25.0`|
|`5 ** 2`|`25`|

دلیلش این است که `math.pow()` آرگومان‌های ورودی را به `float` تبدیل می‌کند و نتیجه را نیز از نوع `float` برمی‌گرداند. در مقابل، عملگر `**` بسته به نوع عملوندها و مقدار توان، می‌تواند نتیجه‌ای از نوع `int` یا `float` تولید کند. برای مثال، وقتی هر دو عملوند از نوع `int` باشند و توان نامنفی باشد، نتیجه نیز معمولاً از نوع `int` خواهد بود.
> پایتون یک تابع داخلی به نام `pow()` هم دارد:
> ```python
> print(pow(5,2)) # 25
> ```

## عبارت‌ها و دستورها (Expressions and Statements)

حالا می‌خواهیم دو مفهوم بسیار مهم را از یکدیگر تفکیک کنیم: Expression و Statement.

این دو اصطلاح در برنامه‌نویسی بارها تکرار می‌شوند و اگر تفاوتشان را درست متوجه نشویم، ممکن است درک رفتار کد برایمان گیج‌کننده شود.

### Expression چیست؟

Expression عبارتی از کد است که هنگام ارزیابی (Evaluation) یک مقدار تولید می‌کند.

شاید در نگاه اول کمی انتزاعی به نظر برسد؛ اما با چند مثال ساده موضوع روشن می‌شود.

!!! example "Python"

	
	```python
	>>> 17
	```
	**Output:**
	
	```text
	17
	```
	

یک Expression است که مقدار `17` را تولید می‌کند.

!!! example "Python"

	
	```python
	>>> 3.14
	```
	**Output:**
	
	```text
	3.14
	```
	

این هم یک Expression است که مقدار `3.14` را تولید می‌کند.

حتی یک String ساده نیز می‌تواند Expression باشد:

!!! example "Python"


	```python
	>>> "Hello"
	```
	**Output:**
	
	```text
	'Hello'
	```


این عبارت مقدار `"Hello"` را تولید می‌کند.

اما Expressionها همیشه به همین سادگی نیستند. می‌توانیم از متغیرها، عملگرها و فراخوانی توابع برای ساخت Expressionهای پیچیده‌تر استفاده کنیم:

```python
n + 25
```
	

یا:

	
```python
math.sqrt(25)
```
	

حتی می‌توانیم چندین Expression را با یکدیگر ترکیب کنیم:

!!! example "Python"

	
	```python
	19 + n + round(math.pi) * 2
	```
	

فرض کن قبلاً مقدار زیر را به `n` اختصاص داده‌ایم:

```python
n = 17
```
	

حالا بیایید عبارت بالا را مرحله‌به‌مرحله ارزیابی کنیم.

ابتدا تابع `round()` مقدار `math.pi` را گرد می‌کند:

!!! example "Python"

	
	```python
	round(math.pi)
	```
	
	**Output:**
	
	```text
	3
	```


حالا عبارت اصلی به این شکل درمی‌آید:

```python
19 + 17 + 3 * 2
```

با رعایت Operator Precedence، ابتدا ضرب انجام می‌شود:

```python
19 + 17 + 6
```

و در نهایت:

```
42
```

دیدی؟ یک Expression می‌تواند از چند Expression کوچک‌تر تشکیل شود و در نهایت یک مقدار تولید کند.

### Statement چیست؟

حالا به مفهوم دوم می‌رسیم.

Statement واحدی از کد است که هنگام اجرا یک عمل یا اثر ایجاد می‌کند؛ اما خودش مانند یک Expression مقدار قابل استفاده‌ای تولید نمی‌کند.

برای مثال:

!!! example "Python"

	```python
	>>> n = 17
	```
	**Output:**
	
	```text
	```

این یک Assignment Statement است.

چه اتفاقی می‌افتد؟

1. Python ابتدا Expression سمت راست را ارزیابی می‌کند.
    
2. مقدار حاصل، یعنی `17`، به دست می‌آید.
    
3. نام `n` به Object مربوط به این مقدار متصل می‌شود.
    

در نتیجه، Assignment انجام شده است؛ اما خود دستور `n = 17` یک Value تولید نمی‌کند.

مثال دیگر:

!!! example "Python"

	
	```python
	import math
	```
	**Output:**
	
	```text
	```
	

این هم یک Statement است.

با اجرای آن، Python ماژول `math` را در صورت نیاز پیدا و بارگذاری می‌کند و نام `math` را در Namespace فعلی در دسترس قرار می‌دهد.

باز هم خود دستور `import math` یک Value تولید نمی‌کند.

### تفاوت Expression و Statement

حالا که هر دو مفهوم را شناختیم، می‌توانیم تفاوتشان را کنار هم ببینیم:

|Expression|Statement|
|---|---|
|هنگام Evaluation یک مقدار تولید می‌کند.|هنگام Execution یک عمل یا اثر ایجاد می‌کند.|
|می‌تواند بخشی از Expressionهای دیگر باشد.|برای اجرای یک دستور استفاده می‌شود.|
|`17 + 5`|`n = 17`|
|`math.sqrt(25)`|`import math`|
|`len("Python")`|`print("Hello")` در قالب یک Expression Statement|

یک نکته ظریف هم وجود دارد که بهتر است همین‌جا روشنش کنیم.

آیا `print("Hello")` یک Expression است یا Statement؟

در واقع، فراخوانی تابع `print("Hello")` یک Function Call Expression است. این Expression هنگام ارزیابی تابع را اجرا می‌کند و مقدار بازگشتی آن را تولید می‌کند.

تابع `print()` متن را نمایش می‌دهد و مقدار `None` را برمی‌گرداند.

اما وقتی این Expression را به‌تنهایی در یک خط می‌نویسیم، آن خط از نظر ساختار زبان یک **Expression Statement** محسوب می‌شود.

پس دو موضوع را با هم اشتباه نگیریم:

- Function Call یک نوع Expression است.
    
- وقتی Expression را به‌صورت مستقل به‌عنوان یک دستور می‌نویسیم، با Expression Statement روبه‌رو هستیم.
    
> احتمالا الان می‌گین که بهداد الان من تو محیط تعاملی REPL که می‌زنم مثلا `print('behdad')` بهم خروجی نشون می‌ده پس چرا تو میگی که این دستور `print()` خروجیش `None` ه؟ اون چیزی که می‌بینین، نتیجهٔ کاریه که تابع `print()` انجام می‌ده، نه مقداری که برمی‌گردونه! این مثال کلا موضوع رو روشن می‌کنه:
> !!! example "Python"
	```python
	result = print("Hello")
	
	print(result)
	```
	**Output:**
	```text
	Hello
	None
	```
> درسته که ما وقتی دستور پرینت رو می‌نویسیم کلمه `Hello` رو نمایش می‌ده ولی وقتی مقدار بازگشتی تابع رو در یک متغیر ذخیره می‌کنیم می‌بینیم که `None` در اون ذخیره شده. (خیلی عجیب بود نه!)

## Evaluation و Execution

تا اینجا دو اصطلاح را چند بار به کار بردیم: Evaluation و Execution.

حالا بیایید دقیق‌تر ببینیم هرکدام به چه معنا هستند.

**Evaluation** یعنی ارزیابی یک Expression برای به‌دست‌آوردن مقدار آن.

**Execution** یعنی اجرای یک Statement برای ایجاد اثر موردنظر.

مثلاً:

!!! example "Python"

	
	```python
	>>> 10 + 5
	```
	**Output:**
	```text
	15
	```
	

یک Expression است. Python آن را Evaluate می‌کند و مقدار `15` به دست می‌آید.

اما:

!!! example "Python"

	
	```python
	>>> x = 15
	```
	**Output:**
	```text
	```
	

یک Statement است. Python آن را Execute می‌کند و نام `x` را به Object مربوط به مقدار `15` متصل می‌کند.

می‌توانیم تفاوت این دو را این‌طور خلاصه کنیم:

|مفهوم|نمونه|نتیجه|
|---|---|---|
|Evaluation|`10 + 5`|تولید مقدار `15`|
|Execution|`x = 15`|ایجاد اتصال بین نام `x` و مقدار `15`|

## تابع `print()`

تا اینجا از Expressionها و Statementها صحبت کردیم، اما هنوز یک سؤال باقی مانده است: چطور نتیجه محاسباتمان را نمایش دهیم؟

برای این کار از یکی از پرکاربردترین توابع Python، یعنی `print()`، استفاده می‌کنیم.

### رفتار محیط تعاملی Python

فرض کن در محیط تعاملی Python، مانند REPL یا Jupyter، دستورات زیر را وارد کنیم:

!!! example "Python"


	```python
	>>> n = 17
	>>> n + 1
	```
	
	**Output:**
	
	```text
	18
	```


چرا نتیجه `n + 1` نمایش داده شد، اما نتیجه دستور `n = 17` را ندیدیم؟

چون محیط تعاملی Python معمولاً نتیجه آخرین Expression مستقل را به‌صورت خودکار نمایش می‌دهد.

حالا اگر دو Expression مستقل بنویسیم چه اتفاقی می‌افتد؟

!!! example "Python"

	
	```python
	>>> n + 2
	>>> n + 3
	```
	
	**Output:**
	
	```text
	20
	```


فقط نتیجه Expression آخر نمایش داده می‌شود.

پس اگر بخواهیم نتیجه هر دو عبارت را ببینیم، چه کار باید کنیم؟

### نمایش چند مقدار با `print()`

راه‌حل ساده است: از `print()` استفاده می‌کنیم.

!!! example "Python"

	
	```python
	print(n + 2)
	print(n + 3)
	```
	
	**Output:**
	
	```text
	19
	20
	```
	

با این کار، هر دو نتیجه به‌صورت جداگانه نمایش داده می‌شوند.

اما یک نکته مهم وجود دارد: این رفتار خودکار مربوط به محیط تعاملی Python است.

اگر همین کد را داخل یک فایل با پسوند `.py` قرار دهیم:

```python
n = 17
n + 1
n + 2
n + 3
```
	

با اجرای فایل، هیچ‌کدام از نتایج به‌صورت خودکار نمایش داده نمی‌شوند.

چرا؟ چون اجرای یک فایل Python با رفتار REPL تفاوت دارد. در فایل‌های `.py`، Expressionهای مستقل صرفاً ارزیابی می‌شوند و نتیجه آن‌ها به‌طور خودکار نمایش داده نمی‌شود.

برای مشاهده نتیجه باید صریحاً از `print()` استفاده کنیم:

!!! example "Python"


	```python
	n = 17
	
	print(n + 1)
	print(n + 2)
	print(n + 3)
	```
	
	**Output:**
	
	```text
	18
	19
	20
	```
	

این تفاوت را خوب به خاطر بسپار؛ چون یکی از اشتباهات رایج هنگام شروع برنامه‌نویسی با Python، انتظار داشتن رفتار REPL از فایل‌های معمولی است.

> احتمالا تا الان براتون سوال بود که چرا بهداد تو مثال هاش یه جا `>>>` می‌ذاره یه جا `print()` احتمالا الان دیگه حل شد براتون خدا رو شکر! (اگر هنوز حل نشد باید بگم که چندخطی ها رو پرینت می‌ذاشتم یک‌خطی ها رو از اون سه تا بیلبیلکی ها. من حواسم به همه چی هست!)
### ارسال چند Argument به `print()`

تا اینجا هر بار یک مقدار را به `print()` ارسال کردیم. اما آیا می‌توانیم چند مقدار را در یک فراخوانی نمایش دهیم؟

بله!


!!! example "Python"

	
	```python
	print('The value of pi is approximately', math.pi)
	```
	
	**Output:**
	
	```text
	The value of pi is approximately 3.141592653589793
	```
	

احتمالاً متوجه شده‌ای که بین دو مقدار یک فاصله وجود دارد.

این فاصله تصادفی نیست! تابع `print()` به‌صورت پیش‌فرض از یک Space برای جداکردن Argumentهای خود استفاده می‌کند.

این رفتار با پارامتری به نام `sep` کنترل می‌شود.

مثلاً:

!!! example "Python"


	```python
	print("Python", "C", "Rust", sep=" | ")
	```
	
	**Output:**
	
	```text
	Python | C | Rust
	```
	

با تغییر مقدار `sep` می‌توانیم جداکننده بین Argumentها را تغییر دهیم.

پارامتر دیگری هم وجود دارد: `end`.

این پارامتر مشخص می‌کند که بعد از نمایش خروجی، چه چیزی چاپ شود. مقدار پیش‌فرض آن کاراکتر خط جدید (`\n`) است. (مثلا این دستور رو تست کنین: `print('hello\nbehdad')`)

مثلاً:

!!! example "Python"

	
	```python
	print("Hello", end=" ")
	print("World")
	```
	
	**Output:**
	
	```text
	Hello World
	```
	

در حالت عادی، فراخوانی اول پس از نمایش `Hello` به خط بعد می‌رود؛ اما با تعیین `end=" "`، به‌جای خط جدید یک فاصله قرار می‌دهیم.

در نتیجه، خروجی فراخوانی دوم در ادامه همان خط نمایش داده می‌شود.

## آرگومان‌ها (Arguments)

تا اینجا چندین بار مقادیری را به توابع ارسال کردیم؛ اما دقیقاً به این مقادیر چه می‌گوییم؟

وقتی یک تابع را فراخوانی می‌کنیم، Expressionهایی که به آن ارسال می‌کنیم Argument نام دارند.

برای مثال:

```python
int('101')
```
	

در اینجا:

- `int` نام تابع است.
    
- `'101'` آرگومان ارسالی به تابع است.
    

> تابع `int()` مقدار ورودی را به یک عدد صحیح تبدیل می‌کند. (اینو از درس های قبل یادتون نرفته که انشالله)

### تعداد Argumentها

توابع مختلف می‌توانند تعداد متفاوتی از Argumentها را دریافت کنند.

برای مثال، تابع `int()` می‌تواند یک Argument دریافت کند:


```python
int('101')
```


اما تابع `math.pow()` به دو Argument نیاز دارد:


```python
math.pow(5, 2)
```
	

Argument اول عددی است که می‌خواهیم به توان برسانیم و Argument دوم توان موردنظر را مشخص می‌کند.

بعضی توابع علاوه بر Argumentهای اصلی، Argumentهای اختیاری نیز دارند.

برای مثال:

```python
int('101', 2)
```
	

در اینجا Argument اول مقدار ورودی و Argument دوم مبنای عدد را مشخص می‌کند.

یعنی به Python می‌گوییم رشته `'101'` را به‌عنوان یک عدد در مبنای ۲ تفسیر کند.

بیایید ببینیم نتیجه چه می‌شود.

عدد `101` در مبنای دو برابر است با:

\[  
1 \times 2^2 + 0 \times 2^1 + 1 \times 2^0  
\]

\[  
= 4 + 0 + 1 = 5  
\]

پس:

!!! example "Python"

	
	```python
	print(int('101', 2))
	```
	
	**Output:**
	
	```text
	5
	```
	

به همین سادگی! با تغییر مبنا، Python رشته ورودی را مطابق سیستم عددی موردنظر تفسیر می‌کند.

### Argument اختیاری در `round()`

مثال دیگری را بررسی کنیم:

!!! example "Python"


	```python
	>>> round(math.pi, 3)
	```
	
	**Output:**
	
	```text
	3.142
	```
	

تابع `round()` برای گرد کردن یک عدد استفاده می‌شود.

در این مثال:

- Argument اول عددی است که می‌خواهیم گرد کنیم.
    
- Argument دوم تعداد رقم‌های اعشار موردنظر را مشخص می‌کند.
    

اما آیا همیشه باید Argument دوم را ارسال کنیم؟

خیر. این Argument اختیاری است.

!!! example "Python"

	
	```python
	>>> round(math.pi)
	```
	
	**Output:**
	
	```text
	3
	```
	

اگر Argument دوم را مشخص نکنیم، تابع عدد را به نزدیک‌ترین عدد صحیح گرد می‌کند.

پس تعداد Argumentهای موردنیاز به تعریف هر تابع بستگی دارد؛ بعضی Argumentها اجباری و بعضی دیگر اختیاری هستند.

## خطای TypeError

حالا فرض کن تابعی را فراخوانی کنیم، اما تعداد یا نوع Argumentهای ارسالی با چیزی که تابع انتظار دارد سازگار نباشد.

چه اتفاقی می‌افتد؟

در بسیاری از این موارد، Python خطای `TypeError` ایجاد می‌کند.

بیایید سه حالت مختلف را بررسی کنیم.

### حالت اول: تعداد Argument بیش از حد مجاز

!!! example "Python"

	
	```python
	>>> float('123.0', 2)
	```
	
	**Output:**
	
	```text
	---------------------------------------------------------------------------
	TypeError                                 Traceback (most recent call last)
	----> float('123.0', 2)
	
	TypeError: float expected at most 1 argument, got 2
	```
	

تابع `float()` حداکثر یک Argument می‌پذیرد؛ اما ما دو Argument برای آن ارسال کرده‌ایم.

در نتیجه، Python نمی‌تواند تابع را با این تعداد Argument اجرا کند و خطای `TypeError` ایجاد می‌شود.

### حالت دوم: تعداد Argument کمتر از مقدار موردنیاز

حالا حالت برعکس را در نظر بگیر:

!!! example "Python"

	
	```python
	>>> import math  
	>>> math.pow(2)
	```
	
	**Output:**
	
	```text
	---------------------------------------------------------------------------
	TypeError                                 Traceback (most recent call last)
	      1 import math
	----> 2 math.pow(2)

	TypeError: pow expected 2 arguments, got 1
	```
	

تابع `math.pow()` به دو Argument نیاز دارد، اما ما فقط یک Argument ارسال کرده‌ایم.

پس این بار تعداد Argumentها کمتر از مقدار موردنیاز است.

### حالت سوم: نوع Argument نامناسب

گاهی تعداد Argumentها کاملاً درست است، اما نوع داده‌ای که ارسال کرده‌ایم با چیزی که تابع انتظار دارد سازگار نیست.

برای مثال:

!!! example "Python"

	
	```python
	>>> math.sqrt('123')
	```
	
	**Output:**
	
	```text
	---------------------------------------------------------------------------
	TypeError                                 Traceback (most recent call last)
	----> math.sqrt('123')

	TypeError: must be real number, not str
	```
	

تابع `math.sqrt()` برای محاسبه جذر به یک عدد نیاز دارد؛ اما ما یک String به آن ارسال کرده‌ایم. در این مثال تعداد Argumentها درست است، اما نوع Argument اشتباه بود.

### جمع‌بندی خطاهای TypeError

حالا می‌توانیم سه حالتی را که بررسی کردیم کنار هم قرار دهیم:

|مشکل|مثال|علت|
|---|---|---|
|Argument بیش از حد|`float('123.0', 2)`|تابع تعداد Argumentهای ارسالی را نمی‌پذیرد.|
|Argument کمتر از حد لازم|`math.pow(2)`|یک Argument موردنیاز ارسال نشده است.|
|نوع Argument نامناسب|`math.sqrt('123')`|نوع داده با ورودی موردانتظار تابع سازگار نیست.|

### چرا TypeError مفید است؟

چون Python بسیاری از اشتباهات مربوط به استفاده نادرست از اشیا و توابع را هنگام اجرا تشخیص می‌دهد و به‌جای ادامه دادن با ورودی نامعتبر، خطا ایجاد می‌کند.

برای مثال، وقتی به تابعی که انتظار عدد دارد یک String ارسال می‌کنیم، Python می‌تواند این ناسازگاری را تشخیص دهد.

البته حواست باشد که هر خطای مرتبط با داده‌ها الزاماً `TypeError` نیست.

برای مثال، ممکن است نوع داده کاملاً درست باشد، اما مقدار آن برای عملیات موردنظر معتبر نباشد. در چنین شرایطی احتمال دارد با خطای `ValueError` روبه‌رو شویم.

پس تفاوت این دو را از همین ابتدا در ذهن داشته باش:

- `TypeError`: نوع داده یا نحوه استفاده از آن برای عملیات موردنظر مناسب نیست.
    
- `ValueError`: نوع داده مناسب است، اما مقدار ارائه‌شده قابل قبول نیست.
