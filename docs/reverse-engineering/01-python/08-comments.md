## توضیحات در کد (Comments)

هرچه برنامه‌ها بزرگ‌تر و پیچیده‌تر می‌شوند، خواندن و فهمیدن آن‌ها هم دشوارتر می‌شود. گاهی حتی وقتی خودمان برنامه‌ای را نوشته‌ایم، ممکن است چند هفته بعد با دیدن بعضی قسمت‌های آن بپرسیم: «اینجا دقیقاً داشتم چه‌کار می‌کردم؟!» (شاید الان براتون این حرف عجیب باشه ولی به من اعتماد کنین وقتی خفن شدین این حرف رو خواهید گفت!)

دلیلش این است که زبان‌های برنامه‌نویسی، زبان‌هایی رسمی (Formal Languages) هستند. آن‌ها قواعد و ساختار مشخصی دارند، اما لزوماً طوری طراحی نشده‌اند که انسان بتواند در نگاه اول به‌راحتی منظور برنامه را متوجه شود.

برای حل این مشکل از Comment استفاده می‌کنیم.

Comment توضیحی به زبان طبیعی است که داخل کد قرار می‌دهیم تا خواندن و درک برنامه برای انسان آسان‌تر شود.

در Python برای نوشتن Comment از علامت `#` استفاده می‌کنیم.

برای مثال:

```python
# number of seconds in 42:42
seconds = 42 * 60 + 42
```


در این مثال، خط اول یک Comment و خط دوم یک Assignment Statement است.

Python هنگام اجرای برنامه، متن Comment را نادیده می‌گیرد و آن را به‌عنوان دستور اجرایی در نظر نمی‌گیرد.

### محل قرارگیری Comment

Comment می‌تواند در موقعیت‌های مختلفی از کد قرار بگیرد.

**حالت اول: Comment در یک خط مستقل**


```python
# Calculate the distance
distance = 100
```


در این حالت، Comment در خطی جداگانه قرار گرفته است.

**حالت دوم: Comment در انتهای خط**

```python
miles = 10 / 1.61  # 10 kilometers in miles
```


اینجا Comment بعد از دستور قرار گرفته است. (از این مدل من قبلا استفاده کردم اگه گفتین کجا؟)

در هر دو حالت، هر چیزی از علامت `#` تا انتهای همان خط، به‌عنوان Comment در نظر گرفته می‌شود.

البته یک استثنای مهم وجود دارد: اگر علامت `#` داخل یک String قرار بگیرد، دیگر Comment نیست!

!!! example "Python"

	```python
	message = "Python # Programming"
	
	print(message)
	```
	
	**Output:**
	
	```text
	Python # Programming
	```
	

چرا؟ چون Python در اینجا علامت `#` را بخشی از مقدار String می‌داند، نه شروع یک Comment.

### چه چیزی را باید Comment کنیم؟

حالا به یک سؤال مهم می‌رسیم: آیا باید برای تمام خطوط برنامه Comment بنویسیم؟

قطعاً نه! Comment زمانی مفید است که اطلاعاتی را ارائه کند که از خود کد به‌راحتی قابل فهم نیست.

مثلاً:


```python
v = 8  # assign 8 to v
```


این Comment چه اطلاعات جدیدی به ما می‌دهد؟

تقریباً هیچ! خود کد به‌اندازه کافی واضح است و مشخص می‌کند که مقدار `8` به نام `v` اختصاص داده شده است.

اما مثال زیر را ببین:


```python
v = 8  # velocity in miles per hour
```


اینجا Comment اطلاعات مفیدی ارائه می‌کند. از روی خود کد نمی‌توانیم بفهمیم `v` نشان‌دهنده چیست، اما Comment مشخص می‌کند که این متغیر سرعت را برحسب مایل بر ساعت نگهداری می‌کند.

پس یک قاعده کاربردی داریم:

**کد باید تا جای ممکن نشان دهد چه اتفاقی می‌افتد و Comment باید اطلاعات تکمیلی، به‌خصوص دلیل انجام آن کار را توضیح دهد.**

### ارتباط Comment و نام‌گذاری متغیرها (Variable Naming)

یک راه دیگر برای خواناتر کردن کد، انتخاب نام‌های مناسب برای متغیرهاست.

فرض کن با این کد روبه‌رو شوی:


```python
v = 3600
```


از روی این نام به‌راحتی نمی‌توان فهمید `v` چه مفهومی دارد.

حالا همین کد را با نامی معنادارتر ببین:

```python
seconds_per_hour = 3600
```


این بار بدون نیاز به Comment هم تقریباً مشخص است که متغیر چه چیزی را نشان می‌دهد.

البته قرار نیست برای هر متغیری یک نام بسیار طولانی انتخاب کنیم. نام‌های بیش‌ازحد طولانی می‌توانند خواندن Expressionها را دشوار کنند.

بنابراین باید بین کوتاهی و وضوح نام‌ها تعادل برقرار کنیم. (گرچه که شما باز کار خودتونو می‌کنین ولی از ما گفتن بود)

## اشکال‌زدایی (Debugging)

همونطور که گفته بودیم Debugging فرایند پیدا کردن، تحلیل و اصلاح مشکلات یک برنامه است.

اما همه خطاها یکسان نیستند. ممکن است برنامه حتی قبل از شروع اجرا با مشکل مواجه شود، ممکن است هنگام اجرا متوقف شود یا حتی بدون هیچ خطایی اجرا شود اما نتیجه اشتباهی تولید کند!

برای درک بهتر، سه نوع خطای مهم را بررسی می‌کنیم:

1. Syntax Errors
    
2. Runtime Errors
    
3. Semantic Errors
    

### خطای نحوی (Syntax Error)

قبل از بررسی این خطا، باید بدانیم Syntax چیست.

Syntax به قواعد و ساختار زبان برنامه‌نویسی اشاره دارد؛ یعنی قوانینی که مشخص می‌کنند دستورات را چطور باید بنویسیم.

مثلاً کد زیر را در نظر بگیر:

!!! example "Python"
	```python
	million! = 1000000
	```
	**Output:**
	
	```text
	million! = 1000000
	       ^
	SyntaxError: invalid syntax
	```
	

این دستور از نظر Syntax معتبر نیست.

چرا؟

چون علامت `!` نمی‌تواند در این موقعیت بخشی از یک نام متغیر باشد.

Python هنگام Parse کردن کد، ساختار آن را مطابق Grammar زبان بررسی می‌کند. وقتی نتواند ساختار معتبری برای دستور پیدا کند، با `SyntaxError` مواجه می‌شویم.

!!! note "نکته مهم"
	خطاهای Syntax معمولاً هنگام Parse شدن کد شناسایی می‌شوند؛ یعنی پیش از اجرای بدنه برنامه.

### خطای زمان اجرا (Runtime Error)

حالا فرض کن کدی از نظر Syntax کاملاً معتبر باشد. آیا تضمینی وجود دارد که هنگام اجرا هم بدون مشکل کار کند؟

خیر!

ممکن است ساختار کد درست باشد، اما هنگام اجرای آن با وضعیتی مواجه شویم که Python نتواند عملیات موردنظر را انجام دهد.

برای مثال:


```python
'126' / 3
```


این عبارت از نظر Syntax معتبر است؛ اما مشکل اینجاست که نمی‌توانیم یک String را مستقیماً بر یک Integer تقسیم کنیم.

نتیجه:

!!! example "Python"

	
	```python
	>>> '126' / 3
	```
	
	**Output:**
	
	```text
	---------------------------------------------------------------------------
	TypeError                                 Traceback (most recent call last)
	----> '126' / 3

	TypeError: unsupported operand type(s) for /: 'str' and 'int'
	```
	

این یک Runtime Error است؛ چون مشکل هنگام اجرای برنامه رخ داده است.

مثال دیگری را بررسی کنیم:

!!! example "Python"

	```python
	>>> x = 10
	>>> y = 0
	>>>
	>>> result = x / y
	```
	
	**Output:**
	
	```text
	---------------------------------------------------------------------------
	ZeroDivisionError                         Traceback (most recent call last)
	      1 x = 10
	      2 y = 0
	      3 
	----> 4 result = x / y
	
	ZeroDivisionError: division by zero
	```
	

در اینجا ساختار برنامه کاملاً معتبر است، اما هنگام تقسیم با صفر مواجه می‌شویم و Python خطای `ZeroDivisionError` ایجاد می‌کند.

Runtime Errorها را در Python معمولاً با مفهوم Exception نیز مرتبط می‌دانیم.

Exception مکانیزمی در Python است که برای نشان دادن شرایط غیرعادی هنگام اجرای برنامه استفاده می‌شود.

چند مثال دیگر:

!!! example "Python"

	
	```python
	>>> int("hello")
	```
	
	**Output:**
	
	```text
	---------------------------------------------------------------------------
	ValueError                                Traceback (most recent call last)
	----> int("hello")
	
	ValueError: invalid literal for int() with base 10: 'hello'
	```


!!! example "Python"
	
	```python
	print(undefined_variable)
	```
	
	**Output:**
	
	```text
	---------------------------------------------------------------------------
	NameError                                 Traceback (most recent call last)
	----> print(undefined_variable)
	
	NameError: name 'undefined_variable' is not defined
	```
	

همان‌طور که می‌بینی، Runtime Errorها می‌توانند دلایل مختلفی داشته باشند. در ادامه یادگیری Python با Exceptionهای بیشتری آشنا خواهیم شد.

### خطای معنایی (Semantic Error)

حالا به جالب‌ترین نوع خطا می‌رسیم!

فرض کن برنامه‌ای نوشته‌ای که:

- Syntax درستی دارد.
    
- بدون Runtime Error اجرا می‌شود.
    
- خروجی تولید می‌کند.
    
- اما نتیجه با چیزی که انتظار داشتی متفاوت است.
    

اینجا با یک Semantic Error مواجه هستیم.

Semantic به معنا و مفهوم اشاره دارد. بنابراین Semantic Error زمانی رخ می‌دهد که برنامه از نظر ساختار و اجرا مشکلی ندارد، اما منطق پیاده‌سازی‌شده با هدف ما مطابقت نمی‌کند.

بیایید یک مثال ساده بررسی کنیم.

فرض کن می‌خواهیم میانگین دو عدد `1` و `3` را محاسبه کنیم.

فرمول میانگین به این شکل است:

\[  
Average = \frac{1 + 3}{2}  
\]

اما اشتباهاً کد زیر را می‌نویسیم:

!!! example "Python"
	
	```python
	>>> 1 + 3 / 2
	```
	
	**Output:**
	
	```text
	2.5
	```


برنامه بدون هیچ خطایی اجرا می‌شود؛ اما چرا نتیجه `2.5` شده است؟

چون Python از قوانین Operator Precedence پیروی می‌کند و اولویت عملگر تقسیم از جمع بیشتر است.

بنابراین ابتدا تقسیم انجام می‌شود:

\[  
1 + \frac{3}{2}  
\]

\[  
1 + 1.5 = 2.5  
\]

درحالی‌که چیزی که واقعاً می‌خواستیم این بود:

\[  
\frac{1 + 3}{2} = 2  
\]

برای اصلاح برنامه باید از پرانتز استفاده کنیم:

!!! example "Python"

	```python
	(1 + 3) / 2
	```
	
	**Output:**
	
	```text
	2.0
	```

<text id="0" />

**نکته:** در این مثال، Python هیچ خطایی گزارش نمی‌کند؛ چون عبارت از نظر Syntax معتبر است و عملیات آن نیز قابل انجام است. مشکل فقط در منطق محاسبه ماست.

به همین دلیل Semantic Errorها گاهی از Syntax Error و Runtime Error دشوارتر هستند. در این حالت، Python لزوماً نمی‌داند که نتیجه موردنظر ما چیز دیگری بوده است. این وظیفه ماست که منطق برنامه و خروجی آن را بررسی کنیم.

## مقایسه سه نوع خطا

حالا که هر سه نوع خطا را بررسی کردیم، بیایید آن‌ها را کنار هم قرار دهیم:

|ویژگی|Syntax Error|Runtime Error|Semantic Error|
|---|---|---|---|
|ساختار کد|نامعتبر|معتبر|معتبر|
|زمان شناسایی|هنگام Parse|هنگام اجرا|معمولاً با بررسی نتیجه|
|پیام خطا|بله|بله|معمولاً خیر|
|وضعیت اجرا|کد معیوب اجرا نمی‌شود|ممکن است برنامه متوقف شود|برنامه اجرا می‌شود|
|مثال|نام متغیر غیرمجاز|تقسیم بر صفر|فرمول اشتباه|
!!! note "پس همیشه یادت باشه"
	اجرای موفق یک برنامه لزوماً به معنی درست بودن آن نیست! گاهی برنامه دقیقاً همان کاری را انجام می‌دهد که به آن دستور داده‌ایم، اما دستوری که نوشته‌ایم از ابتدا اشتباه بوده است.
